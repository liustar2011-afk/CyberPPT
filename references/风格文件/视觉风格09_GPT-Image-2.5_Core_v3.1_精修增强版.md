- Image 2.5 局部编辑时的稳定性规则；
- 作为最终底图时所需的完整视觉完成度。

### 0.2 本文件不负责

以下内容优先由 Stage02 / Page Brief / Artifact Spec 决定：

- 页面使命；
- 核心判断；
- 主导业务关系；
- 阅读路径；

- Exact Visible Text；
- 对象数量；
- 关系方向；
- 时间、责任、范围、状态与事实口径。

1. Exact Visible Text、事实、数字、单位、专有名词、时间、责任、范围、状态；

5. Precision Layer 精修层。

任何视觉规则不得迫使高优先级信息失真、遗漏或缩成不可读小字。

## 01｜Style 09 视觉身份

### 1.1 核心气质

创建正式、成熟、克制、精致、准确的领导汇报正文视觉。

视觉语言：

`premium executive-report design, refined editorial infographic, presentation-grade visual quality, business-class polish, restrained and authoritative, content-led business communication, strong visual hierarchy, controlled spatial rhythm, precise alignment, crisp edges, highly legible Chinese text, clean white canvas, disciplined deep-blue palette, polished micro-geometry, flat matte finish`

页面应像高质量战略汇报、行业研究报告或正式建设方案中的正文信息图，不得呈现为：

- 科技海报；
- SaaS 产品页；
- 数据仪表盘；
- UI 界面；
- 通用模板卡片墙；
- 宣传广告；
- 游戏化或高光 3D 科幻视觉。

### 1.2 高端商务编辑感的来源

高端感不能只靠白底和深蓝，而应主要来自：

- 一个明确主焦点；
- 清楚的阅读路径；
- 非模板化的编辑式空间节奏；
- 舒适且有分级的中文排版；
- 线条、箭头、形状、卡片边界的精细完成度；
- 精准对齐、稳定间距、统一圆角与一致收口；
- 结构关系有“制作完成感”，而不是概念草图感；
- 局部浅蓝关系线与白底的克制高级对比；
- 每个元素都像正式报告中的经过打磨的成品。

### 1.3 配色

主背景：

- 纯白 `#FFFFFF`

主色：

- 深蓝 `#12355B`

辅助层级：

- 蓝灰 `#5B7A99`
- 浅蓝灰 `#E8EEF5`
- 正文 `#303030`
- 次级文字 `#6F7275`
- 分隔线 `#C9CDD1`

条件色：

- 明亮科技蓝 `#1687E8`
  - 非必选；
  - 仅用于唯一主路径、关键交互或明确活动状态；
  - 不作为大面积装饰色。

- 低饱和琥珀色 `#D9772B`
  - 仅用于来源明确的风险、例外、约束、待定或关键决策点；
  - 不用于普通类别区分。

整体保持高对比、低噪声、平面哑光、边缘清楚。

## 02｜可见内容契约

### 2.1 PAGE TITLE

页面主标题仅作为语义上下文。

正文图中：

- 不绘制页面主标题；
- 不生成同义总标题；
- 不固定设置顶部结论条；
- 不为标题保留固定空白带。

### 2.2 EXACT VISIBLE TEXT

如果 Stage02 / Page Brief 已提供 Exact Visible Text：

- 逐字准确；
- 不改写；
- 不增删；
- 不同义替换；
- 数字、单位、时间、对象名按原有语义绑定；
- 每条默认只出现一次；
- 不生成额外说明、随机标签、伪文字或占位文字。

版式必须为 Exact Visible Text 提供可读空间。

### 2.3 EDITABLE CONTENT

仅在上游明确允许改写，且没有给出 Exact Visible Text 时，才允许：

- 短句化；
- 合并重复表达；
- 调整局部顺序；
- 结论先行；
- 形成 1—3 句的局部说明。

必须保留：

- 业务对象；
- 动作；
- 事实；
- 数字；
- 时间；
- 条件；
- 责任；
- 范围；
- 状态；
- 原有结论力度。

不得把完整业务判断压缩为失去业务含义的孤立关键词。

## 03｜构图机制

### 3.1 一个页面只执行一个主导骨架

如果上游提供 `SELECTED LAYOUT RECIPE`，直接执行该骨架。

不得：

- 再从其他版式中重新选择；
- 叠加第二套竞争性结构；
- 因风格偏好把流程页改成中心放射；
- 因条目数量自动生成等权卡片阵列。

### 3.2 SELECTED LAYOUT RECIPE 接口

上游可按以下格式注入：

```text
[SELECTED LAYOUT RECIPE]
type:
dominant_relationship:
reading_path:
primary_focus:
spatial_skeleton:
visual_carrier:
secondary_support:
result_or_end_state:
must_preserve:
do_not:
```

执行规则：

- `dominant_relationship` 决定页面主关系；
- `reading_path` 决定观看顺序；
- `primary_focus` 决定第一视觉入口；
- `spatial_skeleton` 决定空间组织；
- `visual_carrier` 决定主要视觉载体；
- `secondary_support` 只作从属支撑；
- `result_or_end_state` 决定页面收束位置；
- `must_preserve` 不得被视觉优化破坏；
- `do_not` 只约束本页明确不需要的结构。

### 3.3 没有 Layout Recipe 时的回退逻辑

只有在上游没有提供版式骨架时，才根据页面语义选择最简单、依据最充分的一个主结构。

优先判断：

- 是否存在明确顺序；
- 是否存在明确时间；
- 是否存在中心—外围；
- 是否存在因果；
- 是否存在共同维度比较；
- 是否存在组成或支撑；
- 是否存在权责边界；
- 是否由数量关系主导；
- 是否由真实对象或现场动作主导；
- 若均不明显，则采用开敞的并列编辑式分组。

不要在内部同时保留多套候选模板。

## 04｜空间与信息层级

### 4.1 主焦点

正文第一眼必须识别唯一主焦点。

主焦点可以是：

- 关键对象；
- 关键关系；
- 核心机制；
- 重要指标；
- 核心业务场景；
- 关键阶段；
- 结果节点；
- 风险或约束状态。

主焦点通过以下方式建立：

- 尺度；
- 位置；
- 对比；
- 深蓝；
- 局部场景尺度；
- 结构中心性；
- 有依据的空间权重。

不得为了制造视觉中心而压缩必须保留的正文。

### 4.2 空间组织

统一视觉语言，不统一页面骨架。

允许：

- 左到右；
- 上到下；
- 中心向外；
- 汇聚；
- 发散；
- 路径推进；
- 局部聚焦；
- 非对称或均衡分组。

原则：

- 来源存在主次时，允许非对称与不等视觉权重；
- 来源等权时，保持同层均衡；
- 区域大小由语义与文字长度决定；
- 不强制三栏、四卡片、底部横带、中心大图；
- 不按条目数量机械决定版式；
- 优先形成一个主要结构载体，其余信息就近附着。

高级感来自：

`strong hierarchy + accurate alignment + controlled spacing + meaningful whitespace + semantic proximity + restrained contrast + polished boundaries`

## 05｜中文文字与信息密度

### 5.1 字号原则

先保证可读，再安排视觉材料。

正文为基础阅读尺度；局部标题适度放大；必要说明保持接近正文的可读尺寸；小字只用于真正补充性的脚注。

当页面信息较多时，依次处理：

1. 扩大文字承载区域；
2. 调整主次空间权重；
3. 删除无独立语义价值的装饰；
4. 合并重复表达；
5. 压缩允许改写的说明；
6. 最后才考虑轻微缩小字号。

不得以极小字号解决信息过载。

### 5.2 图文分工

每个主要信息点只选择一个主表达载体：

- 文字：判断、定义、动作、责任、条件、范围；
- 数字与图表：规模、比例、趋势、量化比较；
- 对象与场景：现实对象、现场动作、业务语境；
- 空间与路径：组成、流转、依赖、先后、边界。

图与文字不得完整重复表达同一信息。

### 5.3 长文字区域

较长中文文字必须：

- 位于高对比、低细节背景；
- 与图片、线条和边缘保持安全间距；
- 不压在复杂纹理上；
- 不切割数字、单位、对象名和条件；
- 不形成大段密集“说明书式”正文。

## 06｜场景、对象与抽象视觉

### 6.1 场景不是默认项

场景可以为零。

只有当场景能够承担以下至少一项职责时才使用：

- 对象识别；
- 现实证据；
- 空间关系；
- 现场动作；
- 业务情境。

对制度、机制、授权、权责、数据流通、治理类页面，优先表达主体、边界、接入、交换、使用、控制和结果关系。

不要因为主题包含“数据”“平台”“基础设施”就自动绘制机房、服务器、数据中心或发光设备。

### 6.2 实景语言

可按内容使用：

- 电网设施；
- 变电站；
- 输电线路；
- 调度与控制环境；
- 新能源基地；
- 储能；
- 发电设施；
- 工业现场；
- 专业分析环境；
- 教学与培训资源；
- 运营服务环境；
- 文档、资料、工作台、业务载体。

要求：

- 真实；
- 整洁；
- 无品牌化；
- 业务相关；
- 克制；
- 与周边信息结构融合。

通常一个明确的局部场景优于多个泛化小图。

### 6.3 人物

人物不是默认项。

确需人物时：

- 只服务于业务动作；
- 优先侧面、背面、侧后方或自然工作状态；
- 不直视镜头；
- 不形成宣传照；
- 不成为第一视觉入口。

### 6.4 图标

图标只在明显提高识别效率时使用。

一般页面使用极少量：

- 小尺寸；
- 深蓝；
- 简洁；
- 嵌入已有信息组。

不得：

- 一事项一图标；
- 图标墙；
- 圆形徽章阵列；
- 图标流程；
- 用图标替代有来源依据的文字或业务对象。

### 6.5 抽象视觉

允许使用：

- 细线；
- 几何形状；
- 浅蓝关系线；
- 局部色块；
- 边界；
- 结构底面；
- 克制的抽象背景。

这些元素必须承担：

- 分组；
- 引导；
- 关系；
- 边界；
- 连续性；
- 视觉节奏。

不得只为“科技感”存在。

## 07｜Precision Layer｜精修层为硬要求

### 7.1 总原则

Precision Layer 不是后续重建提示，而是本次生图必须完成的成品要求。

页面中的：

- 线条；
- 箭头；
- 形状；
- 卡片；
- 容器；
- 边界；
- 局部底面；
- 摄影窗口边缘；
- 连接节点；
- 结构分隔线；
- 小型强调条；
- 微观留白；
- 对齐收口

都必须在图中体现出“精修后的商务编辑成品感”。

### 7.2 线条层级

必须建立清楚的线条层级，而不是整页一种粗细。

建议至少区分三层：

1. 主关系线  
   - 服务核心结构、主流程、主要连接、关键边界；
   - 视觉上最清楚、最稳定；
   - 一般使用深蓝。

2. 次关系线  
   - 服务局部连接、辅助解释、从属关系；
   - 明显弱于主关系线；
   - 一般使用蓝灰或浅蓝。

3. 微分隔线 / 校准线  
   - 服务分组、分隔、对齐、局部边界与节奏；
   - 细且安静；
   - 不抢主关系。

线条必须表现出“有层级、有手工打磨感”，而不是默认模型画出的均质线。

### 7.3 箭头

箭头必须有商务图形化精修感，不得只是普通示意箭头。

要求：

- 线身纤细、均匀、稳定；
- 箭头头部紧凑、清楚、比例协调；
- 与线身自然衔接；
- 端点锚定明确；
- 同级箭头风格一致；
- 主箭头与次箭头有清楚层级；
- 少转折、少噪声；
- 让出文字与数字；
- 与周边对象保留精确安全距离。

只有来源明确存在方向时才使用箭头。  
双向箭头只在双向交互真实存在时使用。  
虚线箭头只用于待定、条件、反馈或弱约束关系。

视觉锚点：

`precision-drawn vector arrows, slender uniform shafts, compact arrowheads, clean tangent joins, precise endpoints, crisp hierarchy, editorial-grade finish`

### 7.4 形状与边界

形状必须像精修后的信息图组件，而不是普通框图。

要求：

- 轮廓清楚；
- 圆角统一；
- 内外边距舒适；
- 边界不毛糙；
- 白底与浅蓝灰底面切换自然；
- 局部关键对象允许更强存在感；
- 同类容器在圆角、描边、内边距和标题关系上保持一致。

局部弱背景、范围边界、支撑带、信息容器必须有“克制但成品化”的处理，而不是空白上随意摆字。

视觉锚点：

`refined editorial information panels, subtle blue-gray keylines, consistent corner radii, clean matte surfaces, generous controlled padding, crisp understated boundaries`

### 7.5 卡片与开敞分组

优先开敞分组，但只要页面中使用卡片或容器，就必须做到高完成度。

要求：

- 内容驱动尺寸；
- 不强制等高等宽；
- 标题、正文、标签和数字对齐准确；
- 内边距统一；
- 分组关系明确；
- 边缘与线条收口精细；
- 小圆角、细描边、轻量底面；
- 不出现“PPT默认矩形框”的廉价感。

### 7.6 局部底面与结构底座

允许使用局部结构底面、支撑底座或浅层承载面，但必须克制、扁平、精细。

适用对象：

- 核心机制；
- 中心对象；
- 共享底部支撑带；
- 小型数据证据区；
- 流程主链承载面；
- 关系场中的局部结构底面。

要求：

- 轻量哑光；
- 边缘清楚；
- 不做夸张 3D；
- 不做厚重投影；
- 不做未来科幻平台；
- 不做大面积发光底座。

### 7.7 微观几何与对齐

页面必须体现微观几何打磨感：

- 同级元素边界整齐；
- 标注与对象锚点精确；
- 线端、箭头端、卡片边、图片窗边和分隔线之间存在稳定秩序；
- 圆角风格统一；
- 间距具有节奏，不是随机散落；
- 结构元素共享不可见网格；
- 文字与图形的附着关系清楚。

这部分质量直接决定是否呈现“高端商务编辑感”。

### 7.8 材质与完成度

除真实场景对象外，其余信息结构默认使用平面哑光语言。

允许：

- 极浅层体积感；
- 局部柔和阴影；
- 轻微透视；
- 精细边缘高光；
- 白底自然过渡。

但必须克制，不能走向：

- 玻璃拟态；
- 高光 3D；
- 发光边框；
- 水晶 UI；
- 炫技材质。

最终感觉应是：

`meticulously finished, editorial-grade micro-detailing, crisp and polished, restrained premium business finish`

## 08｜底图成品化要求

由于后续默认仅重建文字，因此底图中的以下部分必须直接达到正式汇报成品质量：

- 主体结构线；
- 主次箭头；
- 卡片边界；
- 容器圆角；
- 底部支撑带；
- 结构底面；
- 局部分隔线；
- 关键数字载体；
- 摄影窗口轮廓；
- 局部高亮区域；
- 连接节点；
- 精修层细节。

不得把这些内容当作“后续可再精修”的草图。

### 底图质量判断

如果把所有文字暂时遮住，底图仍应体现：

- 明确层级；
- 清晰主关系；
- 精致结构；
- 精修后的商务编辑感；
- 不是空白 + 字块；
- 不是粗糙框图；
- 不是线稿草图；
- 不是默认 PPT 示意图。

---

## 09｜参考图规则

每张参考图只承担一个主要职责。

### Style Reference

继承：

- 配色；
- 线条；
- 材质；
- 摄影语言；
- 空间节奏；
- 完成度；
- 精修感觉。

默认不继承：

- 页面结构；
- 对象位置；
- 具体文字；
- 业务关系。

### Layout Reference

继承：

- 区域比例；
- 阅读路径；
- 对象相对位置；
- 视觉重心；
- 空间节奏。

默认不继承：

- 业务内容；
- 具体文字；
- 品牌元素；
- 无关材质。

### Subject Reference

只继承指定业务对象、设备、人物或场景身份及关键特征。

### Copy Reference

只继承明确指定的文字、数字、标签和对应顺序。

如果用户只说“参考这张风格图”，默认按 Style Reference 处理；只有明确要求“照这个版式”时，才按 Layout Reference 处理。

---

## 10｜Image 2.5 编辑模式

只有在基于上一版图像修改时启用。

### CHANGE ONLY

只修改用户明确指定的问题。

例如：

- 某段文字；
- 某个数字；
- 某一区域字号；
- 某个场景；
- 某条连接线；
- 某组箭头精度；
- 某一区域空间；
- 某组形状边界；
- 某个颜色；
- 某个多余对象；
- 某个区域的精修度不够。

### PRESERVE

默认保持：

- 页面比例；
- 主骨架；
- 已正确文字和数字；
- 其它对象位置；
- 阅读路径；
- 配色；
- 场景身份；
- 已通过的空间关系；
- 已通过的留白；
- 已通过的线条与形状风格；
- 已通过的视觉风格。

### EXCLUDE

本轮不得：

- 新增文字；
- 补造事实；
- 增加无关人物、图标、卡片或装饰；
- 因局部修改重构整页；
- 改变未被指定的对象身份；
- 改变未被指定的文字层级；
- 用粗糙替换精修过的图形边界。

单轮编辑优先只处理一个主要失败变量。

---

## 11｜全局禁用项

仅保留真正影响结果的边界。

禁止：

- 新增来源未支持的事实、数字、因果、层级、责任、状态、范围或结论；
- 伪文字、随机标签、虚构 UI、虚构刻度、无依据数据；
- 极小字号；
- 平均卡片墙；
- 图标阵列；
- 泛科技装饰；
- 霓虹；
- 全息面板；
- 发光底座；
- 玻璃拟态；
- 水晶数据塔；
- 密集粒子；
- 大面积蓝灰雾化背景；
- 正面人物宣传照；
- 与内容无关的摄影图；
- 与源内容关系冲突的箭头、层级或空间暗示；
- 把制作说明、字段名、提示词或审阅文字绘制到画面；
- 粗糙线条；
- 默认示意箭头；
- 随机圆角；
- 无精修感的普通矩形框。

## 12｜最小内部 QA

图像生成前只做最小必要检查：

1. Exact Visible Text 是否准确；
2. 数字、单位、时间、对象是否绑定正确；
3. 主关系方向是否与 Stage02 一致；
4. 是否只有一个主导骨架；
5. 中文是否清晰可读；
6. 是否出现额外文字；
7. 是否有图片或装饰侵占必要文字空间；
8. 是否出现明显模板化卡片墙、UI 化或低端科技装饰；
9. 线条、箭头、形状、容器是否有明确层级和精修感；
10. 底图是否达到正式汇报可用的成品完成度。

详细 OCR、关系校验、视觉验收、重叠检查和最终版式检查由外部 QA 流程完成。

## 13｜最终视觉收口

最终结果必须呈现：

- 纯白主背景；
- 深蓝核心层级；
- 编辑式商务信息图；
- 高端领导汇报气质；
- 一个明确主焦点；
- 一条自然阅读路径；
- 准确的业务关系；
- 舒适的中文阅读尺度；
- 语义化场景或对象；
- 纤细、精确、克制的结构线；
- 精修后的箭头与边界；
- 统一圆角、统一内边距与稳定微观几何；
- 极少装饰；
- 高完成度；
- 作为最终底图可直接使用。

最终视觉锚点：

`refined editorial infographic, sophisticated composition, strong visual hierarchy, controlled spatial rhythm, semantic visual anchoring, highly legible Chinese typography, precise vector-like linework, polished arrow geometry, refined panel construction, clean white field, disciplined deep-blue hierarchy, restrained matte depth, meticulously finished executive-report polish`

统一 Style 09 的是视觉语言，不是页面骨架。

上游已经决定结构时，Image 2.5 的任务只有一件事：

**把既定业务关系、文字和空间骨架，生成得更准确、更清楚、更精致，并把底图本身做成正式汇报可直接使用的高完成度成品。**

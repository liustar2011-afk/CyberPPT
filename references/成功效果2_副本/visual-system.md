# 视觉风格09：纯白 + 深蓝领导汇报｜GPT Image 2.5 Artifact Spec 执行版

生成的是可直接用于正式汇报的正文成品图，不是概念插画、灵感草图或通用科技海报。先把输入内容编译为可验收的页面规格，再依据页面语义选择主骨架，最后完成文字、视觉对象、几何关系和精修。

画布尺寸、比例、quality、background 等输出参数由本次生图任务或 API 调用层指定，本风格文件不写死参数。页面主标题仅参与语义理解，由 PPT 单独绘制；正文图中不绘制主标题，不重复同义总标题，不预留固定标题区。

下文所有规则均用于生成控制，不得作为文字出现在画面中。图中只呈现输入来源支持、且被判定为应上屏的业务内容。

## 00｜任务契约：先定义成品，再执行风格

### 0.1 成品定义

默认交付物为一张正式汇报正文图，满足以下要求：

- 信息正确：主体、数字、时间、状态、责任、条件、范围和关系方向不失真；
- 结构明确：一个页面使命、一个主导构图机制、一条可追踪阅读路径；
- 中文可读：文字、数字、单位和专有名词清楚，不以极小字号换取信息塞入；
- 视觉有语义：场景、对象、图形、路径和颜色均承担具体业务作用；
- 风格稳定：纯白、深蓝、编辑式商务信息图，克制、精确、完成度高；
- 可继续编辑：生成后若进入局部修改，优先保持已通过区域稳定，不自动重构整页。

### 0.2 输入内容角色

如果任务中存在以下字段，严格按其角色处理；如果没有显式字段，根据输入语义谨慎判定，不自行扩大权限。

#### A. PAGE TITLE｜页面主标题

仅用于理解页面主题、使命和阅读重点。默认不在正文图中绘制，不改写后重复为图内总标题。

#### B. LOCKED COPY｜锁定文字

包括被明确要求逐字保留的标题、专有名词、数字、单位、政策名称、结论、标签、脚注等。

执行要求：

- 逐字准确，不增删、不改写、不同义替换；
- 数值、单位、对象、时间范围作为不可拆分语义块处理；
- 每条默认仅出现一次，除非输入明确要求重复；
- 不生成伪文字、占位文字或额外说明；
- 锁定文字优先于视觉完整性，版式必须为其让出可读空间。

#### C. EDITABLE CONTENT｜允许提炼内容

用于语义理解和上屏重组，可在来源边界内压缩、改写和重组，但必须保留业务对象、动作、事实强度、数字、条件、范围、责任和状态。

不得把完整业务判断压缩成失去含义的孤立标签。优先保留“对象 + 动作/作用 + 必要限定”的完整语义。

#### D. CONTEXT ONLY｜仅供理解内容

背景说明、制作要求、备注、过程稿说明、提示词本身、引用解释等，仅用于理解，不得渲染上屏。

#### E. PAGE BRIEF｜页面任务

如输入明确给出页面使命、核心判断、阅读路径、指定骨架、主视觉或页面约束，其优先级高于本风格文件对结构的自动判定。

#### F. REFERENCES｜参考图

参考图必须按角色使用，详见第 08 章。未被指定继承的构图、文字、主体或风格不得自动混入。

### 0.3 两种执行模式

#### 生成模式

从页面内容生成新图时，先执行第 02 章的 Artifact Spec 内部编译，再选择主骨架并渲染。

#### 编辑模式

基于上一版图片修改时，不重新解释整页。按第 09 章执行 `CHANGE ONLY / PRESERVE / EXCLUDE`，本轮只处理明确失败项。

### 0.4 执行优先级

发生冲突时，按以下顺序裁决：

1. 锁定文字、来源事实、数字、条件、状态、责任、范围与关系方向；
2. 用户明确给出的页面任务、指定结构、保留项和修改项；
3. 页面使命、信息完整性与中文可读性；
4. 语义骨架、信息层级与阅读路径；
5. Style 09 视觉系统；
6. 局部材质、装饰和精修。

任何低优先级规则不得迫使高优先级内容失真、遗漏或缩成不可读小字。

## 01｜固定 Style System：色彩与基础气质

配色：纯白 `#FFFFFF`，深蓝 `#12355B`，明亮科技蓝 `#1687E8`，低饱和琥珀色 `#D9772B`，正文色 `#303030`，次级文字色 `#6F7275`，分隔线色 `#C9CDD1`。

默认视觉关系：

- 纯白承担主体背景；
- 深蓝承担局部标题、关键对象、核心关系和主要文字强调；
- 明亮科技蓝只承担少量主路径、关键节点或明确交互；
- 浅蓝、蓝灰只用于次级连接、局部衬底和轻量边界；
- 琥珀色只用于来源明确的风险、约束、例外、待定或决策重点。

除真实业务场景中的自然明暗外，页面最多保留三种蓝色明度层级。浅蓝衬底只在局部使用，不形成大面积灰蓝背景。整体保持高对比、低噪声、平面哑光、边缘清楚。

整体气质：高端领导汇报、编辑式商务信息图、权威、沉稳、精致、准确、内容驱动。高级感主要来自比例、层级、留白、文字尺度、几何精度、业务对象真实性和细节收口，不依赖光效或装饰堆叠。

固定视觉锚点：

`premium executive-report design, refined editorial infographic, presentation-grade visual quality, restrained and authoritative, content-led business communication, strong visual hierarchy, controlled spatial rhythm, precise alignment, crisp edges, coherent spacing, highly legible Chinese text, clean white canvas, disciplined deep-blue palette, flat matte finish`

## 02｜Artifact Spec 内部编译：先把页面变成“可验收规格”

生成前先在内部完成以下规格编译。字段名称仅用于推理，不得绘制到画面。

### 2.1 OUTPUT｜交付物

明确当前是汇报正文页、流程图、架构图、数据图表、机制图、时间路线或对象说明图。若页面同时包含多种内容，以能够回答页面问题的主类型为准。

### 2.2 PAGE MISSION｜页面使命

用一句内部判断明确：读者看完本页必须理解什么。

页面使命不强制必须是“结论”。定义页、分类页、任务页、机制页可以分别以准确解释定义、清楚呈现分类、说明任务关系或交代权责边界为使命。

### 2.3 LOCKED COPY MAP｜锁定文字映射

识别所有必须准确出现的文字、数字、单位、时间和专有名词，并确定它们分别属于哪个对象、节点、区域或证据。

锁定文字不是装饰元素，不允许被图形替代。

### 2.4 SEMANTIC MAP｜语义地图

从来源中提取：

- 主体；
- 对象；
- 动作；
- 数字；
- 时间；
- 状态；
- 条件；
- 责任；
- 范围；
- 明示关系：先后、因果、组成、关联、权责、比较、证据、并列。

只使用来源明确支持的关系，不凭视觉需要补造层级、闭环、双向交互、比例或优先级。

### 2.5 INFORMATION HIERARCHY｜信息层级

先决定正文第一眼看到什么，再决定阅读起点、展开方向和收束位置。

层级主要通过位置、尺度、字重、对齐、留白和局部对比形成。颜色只承担辅助分级，不把所有内容都做成同等醒目的模块。

### 2.6 MAIN STRUCTURE｜主骨架

从第 04 章选择一个主导骨架。骨架由页面语义决定，不由 Style 09 固定。

每页采用一个主构图机制；局部证据、条件、日期、标签或说明附着于主结构，不另起第二套竞争性骨架。

### 2.7 SEMANTIC VISUALS｜语义视觉

为每个主要视觉材料分配职责：对象识别、现实场景、关系、流程、数量、空间、证据或情境。

每个主要视觉对象只承担它能准确表达的部分。场景负责业务语境，路径负责关系，数字负责数量，文字负责判断与限定。避免图与文字完整重复表达同一信息。

### 2.8 TYPOGRAPHY PLAN｜文字计划

确认局部标题、关键数字、正文、必要说明和脚注的相对层级。先保证可读，再安排视觉材料。

当内容密度高时，依次采用：扩大文字区域 → 调整空间权重 → 删除无独立语义价值的装饰 → 合并重复表达 → 压缩允许改写的说明文字。不得优先缩小字号。

### 2.9 CONSTRAINTS｜边界

仅保留影响结果的关键边界，不用大段负面词替代正向结构。全局禁用项集中在第 10 章。

### 2.10 QA ORDER｜验收顺序

最终检查顺序固定为：

1. 文字、数字、单位、专有名词；
2. 关系方向、层级、范围和权责；
3. 页面使命与主骨架；
4. 中文可读性和信息密度；
5. 场景、对象与业务语义；
6. 配色、线条、材质和完成度。

前一层未通过时，不优先用装饰性精修掩盖问题。

## 03｜文字、标题与信息密度

### 3.1 外部标题与正文画布分工

页面主标题仅作为语义上下文。正文图中：

- 不绘制页面主标题；
- 不新增同义总标题；
- 不建立固定顶部结论条；
- 不为标题预留空白带；
- 正文视觉焦点由关键对象、数字、关系、阶段或主要信息组建立。

正文中具有独立信息价值、且不与页面主标题重复的来源判断可以保留，并与对应证据或对象绑定。

### 3.2 锁定文字优先

锁定文字必须逐字准确、清晰可辨。数字与单位、日期与状态、对象名与对应指标保持邻近绑定。

不得为了版式整齐拆散不可拆分的业务语义，也不得用图标、缩写或伪文字替代明确要求出现的中文。

### 3.3 允许改写文字

允许改写的内容可短句化、层级化和重组，但要求：

- 直接讲业务内容；
- 保留对象、动作和必要限定；
- 保留结论力度，不把“已完成”改成“推进中”，不把“计划”改成“已实现”；
- 保留责任主体、适用条件、时间和范围；
- 不把有实质含义的完整判断改成孤立名词标签。

### 3.4 信息密度与字号

正文是基础阅读尺度；局部标题适度放大；实质性次级说明保持接近正文的可读尺寸；小字只用于真正补充性的脚注。

如果一页出现大量较长中文文本块，先判断是否存在信息架构过载。对允许改写的说明内容进行语义合并；对锁定内容扩大承载空间。图片、装饰和非必要留白优先让位于文字。

长文本区域必须位于高对比、低细节背景上，并与图片、线条、卡片边缘保持清楚间隔。

### 3.5 主表达载体

每个主要信息点选择一个主表达载体：

- 文字：定义、判断、动作、条件、责任、范围和解释；
- 数字与图表：有依据的规模、比例、趋势和比较；
- 对象与场景：识别、空间、现场动作和业务情境；
- 分组、位置与路径：组成、关联、先后、流转和边界。

相邻说明只补充主载体无法准确表达的含义，不做完整复述。

## 04｜页面骨架库：只固定判定方法，不固定页面版式

按“页面使命 → 明示关系 → 主焦点 → 阅读路径 → 主骨架”的顺序判定。两种骨架均适用时，优先选择去掉后会导致页面问题无法回答的那一种；仍难区分时，选择来源依据更充分、附加假设更少、阅读成本更低的结构。

### 4.1 中心放射式｜中心—外围关联

判定信号：存在共同对象，各主体与其发生接入、服务、交换或协作。

阅读结构：共同对象 → 主要关联 → 对应主体与条件。

空间要求：中心可偏置；外围按真实关系分组；来源等权则保持同级。能用接近、分组和对齐说明关系时，不强制连线。

执行锚点：`anchored central object, clearly grouped peripheral relationships, coherent radial organization`

### 4.2 结论证据式｜判断—依据

判定信号：来源存在明确判断，事实、数据或业务证据直接支持该判断。

阅读结构：主要证据 → 次级证据 → 条件与边界；页面主标题已承担总体判断时，不重复生成同义结论。

空间要求：关键证据获得更大空间；等权证据保持同级；数字、对象和解释就近绑定。

执行锚点：`evidence-led body composition, clearly attached supporting evidence, coherent evidence grouping`

### 4.3 主链流程式｜动作与流转

判定信号：明确存在步骤衔接、对象流转或输入—处理—输出。

阅读结构：起点/输入 → 顺序动作 → 输出；只有来源明确反馈时才形成回流。

空间要求：一条主链贯穿主要画幅；阶段名称、动作和对象直接附着节点；分支只在对应节点局部展开。

执行锚点：`clear sequential flow, anchored stages, explicit input-process-output path`

### 4.4 时间路线式｜时间与状态变化

判定信号：时间节点、阶段状态、里程碑或目标节奏构成主要逻辑。

阅读结构：时间 → 状态 → 阶段成果或条件。

空间要求：日期与状态绑定；真实时间比例只在数据支持时采用；未来事项保持“目标、计划、拟”等原有语气。

执行锚点：`clearly aligned dates and states, legible chronological progression, milestone-led timeline`

### 4.5 因果分析式｜原因、条件与结果

判定信号：来源明示原因或条件如何导致结果。

阅读结构：原因/条件 → 作用过程 → 结果。

空间要求：用汇聚、发散或级联表达真实因果；条件附着于相应环节；风险和约束可局部使用琥珀色。

执行锚点：`explicit cause-and-effect direction, condition-aware causal structure, clearly anchored outcomes`

### 4.6 比较式｜共同维度下的差异

判定信号：两个或多个对象具有共同指标、条件、模式或状态。

阅读结构：比较维度 → 各对象 → 差异及条件。

空间要求：共享基准轴或对齐行列；同一维度保持一致尺度；只有来源明确重点才增加视觉权重。

执行锚点：`shared reference axis, aligned comparison dimensions, clear correspondence between compared items`

### 4.7 组成能力式｜组成、依赖与支撑

判定信号：来源明示整体与部分、能力依赖，或多项能力共同支撑目标。

阅读结构：整体 → 组成/依赖 → 能力及条件。

空间要求：组成用包含与分组；依赖用层级或连接；共同支撑用共享基座或作用范围。独立能力保持并列等级。

执行锚点：`clear whole-part organization, coherent capability grouping, legible layered hierarchy`

### 4.8 机制权责式｜主体、权限与边界

判定信号：重点是主体分工、授权、权属、控制范围或协作机制。

阅读结构：主体 → 权利/责任 → 交互动作 → 适用条件。

空间要求：责任附着主体，授权和交换附着路径，共性规则显示作用边界。双向箭头、回流和层级必须有来源依据。

执行锚点：`boundary-aware composition, explicit responsibility mapping, clearly anchored interactions`

### 4.9 并列分类式｜定义、分类与任务集合

判定信号：来源提供同一维度的分类、任务、主体或事实集合，主要关系为并列；缺少其他明确主关系时也可采用。

阅读结构：共同主题由外部标题提供 → 图内按来源顺序或分类逻辑展开。

空间要求：开敞分组、分栏、共同基线或简洁行列；等权内容保持均衡；文字长度决定区域大小，不强制等宽等高卡片。

执行锚点：`balanced peer grouping, clear categorical organization, open editorial layout, consistent alignment`

### 4.10 数据指标式｜数量关系主导

判定信号：规模、比例、趋势或数值比较本身是主要论据。

阅读结构：核心指标/图形 → 单位、对象、时间 → 解释与口径。

空间要求：图表只使用真实数据；比例需要明确分母，趋势需要真实序列。孤立指标可用大数字，但必须绑定对象、单位和时间范围。

执行锚点：`data-led composition, clearly labeled quantities, consistent quantitative scale`

### 4.11 场景／对象主导式｜空间与现场动作主导

判定信号：理解现实对象的部位、空间位置或现场操作，是回答页面问题的关键。

阅读结构：对象整体 → 相关部位/动作 → 就地说明与条件。

空间要求：对象获得足够识别空间；标注锚定对应部位；对象朝向、裁切和留白共同形成阅读路径。

执行锚点：`object-led composition, spatially anchored annotations, integrated local callouts, controlled contextual crop`

确定主骨架后，只启用该骨架必要的构图逻辑。其他骨架不作为隐性模板叠加。

## 05｜构图与信息层级：避免“同一版式”和“卡片墙”

页面骨架随内容变化，Style 09 只固定视觉 DNA，不固定三栏、四卡片、中心大图、底部能力区等空间模板。

构图原则：

- 第一眼必须识别正文主焦点；
- 阅读方向由语义决定，可左到右、上到下、中心向外、路径推进或局部聚焦；
- 来源存在主次时，可采用非对称与不等视觉权重；来源等权时保持同层均衡；
- 优先形成一个主要结构载体，再让次级信息就近附着；
- 不以“模块化”自动推导为平均卡片阵列；
- 不因追求留白而压缩必要文字；
- 不因文字较多而把所有视觉对象缩成装饰小图。

当多个区域并存时，区域数量和占位由实际语义决定。不要为了满足某个固定数字强行拆成 3 区、4 区或 5 区。

空间高级感来自：主次清楚、局部密度有差异、对齐准确、组间间距明确、文字与对象紧密绑定、空白具有方向性。

构图质量锚点：

`sophisticated editorial composition, strong visual hierarchy, controlled spatial rhythm, integrated text-and-visual composition, semantic visual anchoring`

## 06｜视觉材料选择：每个图像对象都必须“有职责”

### 6.1 场景使用原则

场景按需使用，可以为零。使用场景时，必须承担对象识别、现实证据、空间关系、现场动作或业务情境中的至少一项独立价值。

通常一个清晰的局部场景比多个泛化小图更有效。只有多个场景分别承担不同必要语义时才同时使用。

场景采用真实、整洁、无品牌化的商务或电力业务语境。电力内容可根据语义选择输电线路、变电站、调度环境、新能源基地、储能、发电设施、分析工作环境、教学资源或专业服务场景。

数据流通、制度、授权、机制类页面优先可视化主体、边界、接入、交换、使用和控制关系；只有来源涉及算力、存储或物理设施时，机房、机柜、服务器才作为主要场景。

### 6.2 场景与文字融合

场景可采用局部摄影窗口、准确裁切、柔化边缘或白底自然过渡。文字与其支持的对象形成同一局部语义单元，避免“左边一张泛图、右边一段独立文字”的松散拼接。

场景不复述完整文字。文字负责判断、条件、解释和限定；场景负责语境、对象和动作。

### 6.3 人物

人物只在业务动作确需时出现，并从属于环境。优先侧面、背面、侧后方或自然工作状态，视线指向设备、屏幕、资料或业务对象，不直视镜头，不形成宣传照式主视觉。

人物比例由场景作用决定，不因“商务感”自动放大人物。

### 6.4 图标与抽象视觉

图标只用于提高必要对象的识别效率，使用简洁深蓝矢量符号并嵌入已有信息组。不要为每条文字配置一个图标。

抽象线条、几何形状、色块和装饰背景可以使用，但必须承担分组、引导、关系、边界或视觉节奏作用。无业务语义的圆环、底座、发光体、重复节点和密集纹理不使用。

### 6.5 场景内部文字

场景中的建筑、设备、屏幕、文件、标牌和人物服饰默认不出现日期、Logo、企业名称或随机文字。来源要求出现的机构、日期、企业或数据，作为场景外的正式正文或独立标注呈现。

## 07｜Precision Layer：线条、箭头、形状、卡片与材质

### 7.1 关系优先使用空间，而不是先画线

优先通过接近、对齐、分组、包含和共享基线建立关系。只有跨区域关系、方向、流转、授权或因果需要显式表达时才使用连线。

| 语义 | 几何表达 | 默认处理 |
|---|---|---|
| 流转、先后、作用方向 | 带箭头路径 | 主路径深蓝，次级路径浅蓝/蓝灰 |
| 无方向关联 | 无箭头连线 | 两端锚定、路径短、少转折 |
| 范围、控制边界 | 完整或明确开口轮廓 | 浅蓝灰细描边 |
| 分类、阅读分组 | 对齐留白或分隔线 | 低对比、安静 |
| 条件、反馈、待定 | 有标签的虚线或对应路径 | 同页语义一致 |

### 7.2 箭头

箭头只表达来源支持的方向。使用纤细等宽线身、小型闭合实心三角箭头、清晰端点和一致比例。

默认比例：箭头长度约为线身宽度的 4—6 倍，最宽处约为 3—4 倍；同级箭头大小一致。直接关系用直线，跨区域绕行用少量圆角折线，真实反馈用平滑弧线。

箭头从明确锚点出发，在目标边缘清楚结束，避开文字与数字。双向箭头只在来源明确双向交互时启用。

执行锚点：

`precision-drawn vector arrows, slender uniform shafts, compact filled triangular arrowheads, consistent arrowhead proportions, tangent-aligned arrow tips, precise endpoint spacing, crisp flat matte finish`

### 7.3 形状与边界

- 细线轮廓：范围与控制边界；
- 浅蓝灰面：局部弱背景；
- 深蓝实心面：来源明确的关键对象或节点；
- 琥珀色：风险、约束、例外、待定；
- 嵌套区域：来源明确的组成；
- 摄影窗口：具体业务对象和现实证据。

同类形状保持一致圆角、描边和内边距。高级感来自精确几何、干净轮廓和一致收口，不使用厚重投影或复杂表面效果。

### 7.4 卡片

卡片只在业务信息本身具有明确独立边界时使用。能通过开敞分组表达时，不增加容器。

卡片采用纯白或极浅蓝灰哑光面、低对比细描边、小圆角、舒适内边距和准确文字对齐。尺寸由内容决定，不为追求整齐强制等高等宽。

等权事项保持一致等级；有来源依据的重点通过占位、字重和有限深蓝强调，不依赖更多阴影、徽章或颜色。

执行锚点：

`refined editorial information panels, restrained small-radius corners, subtle blue-gray keylines, clean matte surfaces, generous consistent padding, precise typographic alignment, content-driven proportions, crisp understated edges`

### 7.5 真实对象材质

仅真实业务对象允许轻微体积、透视、局部高光和柔和照明；普通信息容器、图标、箭头和文字底面保持平面哑光。

执行锚点：

`subtle matte surfaces, restrained material contrast, shallow dimensional relief, clean white background, limited deep-blue and bright-blue accents`

### 7.6 精修

精修只围绕已确定结构进行：统一边距、基线、端点、圆角、线宽、箭头、局部留距和跨区域连续性。不得在精修阶段重新发明页面结构。

线条锚点：`precise editorial linework, consistent stroke hierarchy, clean rounded joins, intentional anchor points, elegant line termination`

形状锚点：`controlled vector geometry, crisp contours, consistent corner radii, clean silhouette separation`

## 08｜参考图：一张图一个职责

多参考图不得笼统“综合参考”。必须为每张图指定角色。

### 8.1 Layout Reference｜版式参考

只继承：区域比例、阅读路径、对象相对位置、视觉重心和空间节奏。

不得自动继承：具体文字、业务对象、品牌元素、配色和材质，除非另有明确要求。

### 8.2 Style Reference｜风格参考

只继承：配色、线条、材质、摄影语言、细节精度、边缘处理和整体完成度。

不得自动继承：布局、对象位置、具体文字和业务结构。

### 8.3 Subject Reference｜主体参考

只继承：指定业务对象、设备、人物、场景的身份、外观和关键特征。

不得自动继承：背景构图、配色、文字和无关对象。

### 8.4 Copy Reference｜文字/内容参考

只继承：明确要求使用的文字、数据、标签和对应顺序。

不得自动继承：视觉样式、背景和无关排版。

### 8.5 当前 Style 09 的参考图默认角色

如果用户仅说明“参考这张风格图”，默认将其视为 `Style Reference`，主要继承配色、线条、材质、摄影处理和完成度；页面结构仍由当前页面语义决定。

如用户明确要求“照这个版式”，才把对应图片提升为 `Layout Reference`。

## 09｜编辑模式：CHANGE / PRESERVE / EXCLUDE

当输入包含上一版成图并要求修改时，优先进入局部编辑模式，不重新生成整页设计逻辑。

### 9.1 CHANGE ONLY｜本轮唯一修改项

只修改用户明确指定的问题，例如：

- 某段文字；
- 某个数字；
- 某一区域字号；
- 某个场景；
- 某条箭头；
- 某个颜色；
- 某一区域空间分配；
- 某个多余对象。

### 9.2 PRESERVE｜必须保持

除修改项外，默认保持：

- 页面比例；
- 主骨架；
- 已正确文字与数字；
- 其它对象位置；
- 阅读路径；
- 配色；
- 线条家族；
- 视觉风格；
- 场景身份；
- 已通过的空间关系与留白。

### 9.3 EXCLUDE｜本轮不得发生

- 不新增文字；
- 不补造事实或数字；
- 不自动增加人物、图标、卡片或装饰；
- 不因局部修改重排其它区域；
- 不改变未被指定的主体身份、产品几何、场景类型或文字层级。

### 9.4 单变量迭代

每轮只处理一个主要失败变量。推荐顺序：

1. V0：信息结构；
2. V1：文字、数字、单位和字号；
3. V2：业务场景与语义视觉；
4. V3：留白、对齐和空间权重；
5. V4：线条、边缘、材质和细节；
6. V5：最终验收，不再增加新要求。

发现漂移时，重复本轮 `PRESERVE` 条件，而不是重写整套风格文件。

## 10｜全局边界：只保留真正影响结果的禁用项

以下边界全页适用：

- 不新增来源未支持的事实、数字、因果、层级、责任、状态、范围或结论；
- 不生成伪文字、虚构刻度、虚构 UI、无依据数据或随机标签；
- 不用极小字号、模糊图形或隐藏方式替代必要业务内容；
- 不用面积、距离、颜色、箭头或层级暗示来源未支持的优先级、比例和关系；
- 不把所有内容自动转成平均卡片墙或重复图标阵列；
- 不使用无语义的泛科技装饰替代真实业务表达；
- 不使用大面积蓝灰雾化背景、脏白渐变、玻璃拟态、霓虹边缘、全息面板、发光底座、悬浮光环、透明圆柱、能量粒子、水晶数据塔等廉价未来科技物件；
- 不使用无关 Logo、水印、品牌标识和随机场景文字；
- 不让正面人物宣传照成为默认主视觉；
- 不把提示词、审阅说明、字段名或制作指令绘制到页面。

正向结构已经清楚时，不继续增加同义禁用词。

## 11｜输出前 QA：按“内容 → 结构 → 阅读 → 语义 → 视觉”验收

完成图像前，在内部逐项检查并修正。检查内容不绘制上屏。

### 11.1 文字与事实

- 锁定文字是否逐字准确；
- 数字、单位、时间和对象是否绑定正确；
- 专有名词是否正确；
- 是否出现任何未提供的额外文字；
- 状态、条件、责任、范围和结论力度是否保持来源原意。

### 11.2 关系与结构

- 主骨架是否直接回答页面使命；
- 箭头、边界、层级、先后和因果是否有来源依据；
- 页面是否只有一个主导构图机制；
- 是否误把并列关系画成层级、闭环或因果。

### 11.3 可读性

- 正文第一眼是否能识别主焦点；
- 阅读路径是否自然；
- 中文是否在正常观看距离下清楚；
- 是否出现不必要的小字、拥挤、重叠或长段堆积；
- 是否有图片或装饰侵占必要文字空间。

### 11.4 语义视觉

- 每个主要图片、对象、图标和抽象图形是否有明确职责；
- 场景是否真正对应业务，而不是泛化“科技感”；
- 图与文字是否重复完整表达同一内容；
- 人物是否抢占不必要的视觉中心；
- 参考图是否只继承被指定的角色。

### 11.5 视觉系统与精修

- 配色是否保持纯白 + 深蓝主体系；
- 明亮科技蓝与琥珀色是否克制；
- 同级线条、箭头、圆角、内边距是否一致；
- 对齐、边缘、端点、裁切和局部间距是否精确；
- 是否出现禁用的发光、玻璃、全息或低端 3D 科技元素。

如果只发现局部问题，只修正对应区域，并保持其他已通过项不变。

## 12｜最终风格收口｜最高视觉优先级

最终结果应呈现：纯白、深蓝、编辑式、高端、精确、克制、内容驱动的领导汇报正文图。

核心视觉要求：

`refined editorial infographic, sophisticated editorial composition, strong visual hierarchy, controlled spatial rhythm, integrated text-and-visual composition, semantic visual anchoring, polished, meticulously finished, restrained and authoritative`

构图由当前页面语义决定。来源存在主次时允许 `intentional asymmetry` 与 `unequal visual weight`；来源等权时采用 `balanced peer grouping`。不将任何一种构图方式固化为整套页面模板。

最终高级感必须来自清晰信息层级、真实业务语义、舒适中文尺度、准确空间关系、精细矢量线条、克制材质和一致收口。视觉风格不得凌驾于内容事实、结构正确性和可读性之上。

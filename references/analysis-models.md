# Analysis Models — Reasoning Lenses for Source Material

## Purpose

Use these models during UNDERSTAND and PLAN to discover defensible latent logic in formal Word source material. They are analytical lenses, not slide templates. The source chapter structure remains the default structural authority.

For every selected model, record whether the key relation is `explicit` or `inferred`, identify supporting facts, and reject the model if it requires a speculative premise.

## 1. Problem diagnosis

`observable condition -> problem -> constraint / cause -> capability gap / necessity`

Use when several source paragraphs describe pressures, difficulties, fragmented resources, rising requirements or incomplete mechanisms.

Entry conditions:
- at least two facts describe a shared problem space;
- the diagnosis can be expressed without adding a new external fact.

Avoid:
- turning every list of shortcomings into one causal chain;
- claiming a condition is necessary when the source only says it is useful.

## 2. Situation–tension–response

`existing situation -> change / pressure -> tension -> response need`

Use when the source describes an operating context followed by new pressures or requirements.

Useful for policy background, industry change and transformation materials.

## 3. Causal / enabling chain

`driver -> mechanism -> direct effect -> downstream implication`

Use when facts reveal a real mechanism, even if the source does not draw an arrow explicitly.

Entry conditions:
- the mechanism can be stated from source facts;
- no new intermediate factual event is required.

Avoid:
- chronology = causality;
- paragraph order = dependency;
- category order = progression.

## 4. Problem-to-response mapping

`problem dimension -> response capability / mechanism -> expected role`

Use when one source section states problems and another states corresponding capabilities or positioning.

Mapping may be `inferred` when the correspondence is analytically clear. Do not claim the source explicitly defined a one-to-one mapping unless it did.

## 5. Resource transformation

`resource / capability -> governance / processing -> product / service -> application / value`

Use for data, knowledge, models, platforms, productization and operating systems.

Avoid adding stages that are absent from the source merely to complete a preferred value chain.

## 6. Actor collaboration

`actor -> responsibility / contribution -> interaction object -> handoff / accountability -> joint result`

Use for multi-party platforms, governance, operating models and collaboration mechanisms.

Preserve whether one organization can hold multiple roles and whether responsibilities are mandatory, optional or contract-specific.

## 7. Capability layering

`foundation -> enabling capability -> service capability -> application`

Use only when the source supports actual hierarchy or dependency.

If the source presents a taxonomy of peer services, keep it as a taxonomy. A classification is already a valid presentation structure.

## 8. Maturity / reuse progression

`validation -> configuration / sedimentation -> standardization -> scale`

Use when the source explicitly or inferentially supports transition conditions between maturity states.

A progression must preserve optionality: if modes may be adopted independently as well as deepened over time, say both.

## 9. Risk–control–protection

`risk / concern -> control mechanism -> boundary / responsibility -> protected outcome`

Use for data rights, security, model governance, quality, service level and exit management.

Do not convert a control into a guarantee stronger than the source.

## 10. Value formation

`capability -> use case -> deliverable -> beneficiary -> operational / decision value`

Use when a source lists capabilities and target groups but leaves the value link implicit.

Value statements must name the concrete beneficiary and result; avoid generic value language.

## 11. Evidence synthesis

`judgment -> evidence set -> interpretation -> bounded implication`

Use when several facts collectively support a stronger page-level judgment.

This is the preferred model for turning formal report evidence into a consulting-style analytical page without adding new facts.

## Model-selection procedure

For each source section:

1. identify the source facts and explicit relationships;
2. test one or more candidate models;
3. choose the smallest model that adds explanatory value;
4. label each material relation `explicit` or `inferred`;
5. record support fact IDs for inferred relations;
6. reject any link requiring a new external premise;
7. hand the validated logic to PLAN/AUTHOR.

## Depth floor and ceiling

Depth floor: avoid simple Word-bullet-to-slide-bullet conversion when a defensible analytical relationship is available.

Depth ceiling: stop before the analysis introduces a new fact, unsupported causality, universal claim, necessary condition, ranking, forecast or commitment.

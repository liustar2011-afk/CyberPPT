# Stage 01 提纲与页面脚本稳定性改进设计

## 目标

在不增加新阶段、工作流引擎或多智能体平台的前提下，提高“Source Truth → Outline → 页面脚本”的内容稳定性。继续复用现有 `outline-audit` 与 `script-audit`，只补足页面独特贡献、证据消费边界和内容复核状态。

## 一、扩充现有 Outline 页合同

每个内容页增加四个字段：

- `page_job`：本页在全篇中唯一完成的任务；
- `proof_points`：本页各支撑点、对应 Source ID 及其证明对象；
- `new_value_vs_previous`：相比前置页面新增的判断或信息；
- `reserved_for_later`：明确留给后续页面展开的内容。

四个字段只用于内容规划和审计，不进入上屏文字，也不进入 ImageGen。

严格模式下四个字段必须存在且非空；非严格模式保持兼容。

## 二、约束证据消费与跨页推进

在现有 Outline 审计中增加两类检查：

1. 总述页可以引用后续分述页的证据，但必须在 `reserved_for_later` 中声明分述内容，且总述页的 `page_job` 只能承担框架、定位或取舍，不得声称已经完成详细展开。
2. 相邻或具有前置关系的内容页必须填写 `new_value_vs_previous`；内容与前页任务、证明对象和证据集合高度重合时，给出重写问题，要求合并页面或重新切分页面职责。

不建立复杂的“证据所有权数据库”。审计只读取现有 Outline JSON，使用字段、Source ID集合和文本相似度完成检查。

## 三、区分结构通过与内容复核

`script-audit` 保留现有结构和证据检查，但调整最终状态：

- 存在错误：`rewrite_required`；
- 无错误，但“单一使命、模块同维度、信息取舍、跨页新增价值”尚未确认：`content_review_required`；
- 结构检查和内容复核均完成：`passed`。

项目通过一个简单的内容复核记录确认上述四项，不增加新的工作流阶段。复核记录放在现有脚本审计目录，并绑定当前脚本哈希；脚本变化后自动失效。

## 四、当前项目迁移

对当前项目只做一次性内容迁移：

- 为24个内容页补齐四个新字段；
- 重点重切 P10/P14–P18、P11/P19–P23、P12/P26/P28/P31 的总述与分述边界；
- 重新运行 Outline 审计；
- 重新生成或修订受影响页面脚本；
- 重新运行 Script 审计并形成内容复核记录。

不改变 Source Truth，不进入 Stage 02，不修改视觉风格和生图合同。

## 五、验证

- 旧版非严格 Outline 继续通过兼容测试；
- 严格 Outline 缺少四字段时必须失败；
- 总述/分述职责重叠与无新增价值页面必须被识别；
- 未完成内容复核的脚本不得显示为 `passed`；
- 复核记录与脚本哈希不匹配时自动回到 `content_review_required`；
- 当前项目 Outline、完整脚本和已有相关测试全部通过。

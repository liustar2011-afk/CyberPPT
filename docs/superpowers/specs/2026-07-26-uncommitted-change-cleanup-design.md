# 未提交修改整理与提交设计

## 目标

把当前工作区的真实代码修改与权限、行尾、项目产物噪声分开；只提交边界清晰、可以验证、能够独立回退的修改，不把仓库整理扩大成重构工程。

## 提交分组

### 1. Style 09 视觉语法补交

- 仅提交 `scripts/dual_image_overlay/visual_grammar.py`。
- 确认其输出与已经提交的 Style 09 精简提示词测试契约一致。
- 目的：保证新检出仓库后可以复现当前提示词。

### 2. 工作区噪声清理

- 对内容与 `HEAD` 完全相同、仅权限或 CRLF 行尾变化的文件恢复 Git 记录状态。
- 不改动任何存在真实文本差异的文件。
- 不删除未跟踪项目产物。

### 3. Stage 01 合稿与审阅

- 将 `assemble-final-script`、最终稿形式检查、演讲者备注检查、上屏文字沟通审阅及对应测试作为一个独立功能提交。
- 修复当前 CLI 回归测试与实际门禁顺序不一致的问题。
- 专项测试和相关 CLI 测试全部通过后才能提交。

### 4. Stage 02 图片与模板导出

- 将 1680×944 生图归一化、正文区域适配、封面/目录/章节页识别、封面字段清理、备注消费和背景衔接作为独立提交。
- 补充尺寸归一化、页面角色、封面字段和正文区域测试。
- 只在相关测试通过后提交。

## 不纳入提交

- `scripts/format_procurement_docx.py`：一次性 Word 格式化脚本，依赖外部环境变量且与 CyberPPT 主流程无关。
- 大量项目运行产物、临时文件及历史生成文件。
- 只有权限或行尾变化而无内容变化的文件。

## 验证与提交约束

- 修改任何已有函数前先运行 GitNexus upstream impact。
- 每个提交只包含一个上述分组。
- 提交前运行对应测试、`git diff --cached --check` 和 GitNexus `detect_changes --scope staged`。
- 保留用户已有的其他真实修改，不覆盖、不回退、不混入提交。

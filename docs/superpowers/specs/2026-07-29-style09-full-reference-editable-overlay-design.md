# Style 09 送图脚本修订设计

日期：2026-07-29  
状态：用户已选择方案 A，并明确边界为“仅修订送图脚本”  
适用范围：CyberPPT `content-first-v1` 的逐页 ImageGen 提示词编译

## 1. 边界

本次只修改送给 ImageGen 的逐页脚本及其编译规则。

明确不修改：

- 现有双图法；
- full/background 生成关系；
- manifest 和 production mode；
- OCR、语义计划、editable-overlay 和 PPT 重建；
- 终稿脚本的事实、判断、页面结构和审批流程；
- Style 01–08、Style 10 的默认行为。

## 2. 当前脚本问题

1. `image_locked_text` 被误当成 full 图的全部可见正文，P09 最终只剩两个短标签。
2. 完整上屏正文虽然放在“用于视觉叙事”区，却又被指令要求不得生成长正文，形成自相矛盾。
3. 自动版式把 `decision_canvas`、`no_scene` 等内部枚举直接送入 ImageGen，诱导中心圆、空场景和固定母题。
4. Style 09 的克制规则与过短文字、无场景、禁止多种载体叠加后，容易共同收敛为空洞概念海报。
5. 现有测试只检查字段存在，没有检查最终送图脚本是否保留完整页面内容。

## 3. 修订目标

1. full 图送图脚本必须包含获批的完整上屏内容，能够独立生成一页完整、可审阅的正式汇报画面。
2. `image_locked_text` 只标识必须逐字准确的重点，不再删除其他正文。
3. 自动生成时不把内部母题和场景角色写进提示词。
4. 页面差异来自业务关系、内容主次和页面逻辑，不来自固定模板轮换。
5. Style 09 继续保持文字主导、编辑式克制、单一视觉媒介和局部语义锚点。
6. 明确禁止中心圆、中心徽章、三行大字和少量口号加大面积空白等退化结果。

## 4. 提示词结构

`content-first-v1` 每页按以下顺序编译：

1. `【页面任务｜仅供理解，不上屏】`
2. `【核心判断｜仅供理解】`
3. `【页面逻辑｜不上屏】`
4. `【锁定关键文字】`
5. `【完整上屏内容】`
6. `【内容与视觉要求｜不上屏】`
7. `【输出与风格｜不上屏】`

### 4.1 锁定关键文字

锁定关键文字包括：

- 必须逐字准确的正文结论；
- 模块标题；
- 关键数字、单位、专有名词；
- 否定边界和禁止性表述。

锁定清单用于提高文字准确性，不表示只有这些文字需要上屏。

### 4.2 完整上屏内容

完整上屏内容使用终稿脚本的获批 `上屏结论` 和 `上屏文字`：

- 所有模块及其关键要点均需表达；
- 允许调整换行、层级和局部语序；
- 不得删除支持页面判断成立所必需的内容；
- 不得把解释性正文全部转成图片、图标或抽象视觉隐喻；
- 不再出现“其余正文后续由可编辑层承载、不要求 ImageGen 生成”的指令。

## 5. 自动版式边界

### 5.1 自动决策

- `layout_motif`、`scene_role` 可继续作为内部诊断和批次 QA metadata。
- 自动决策不得进入实际 ImageGen prompt。
- 自动提示词只描述页面需要证明的业务关系、内容主次和阅读路径。

### 5.2 显式覆盖

只有终稿脚本明确填写 `版式母题` 或 `场景角色` 时，才把它们作为人工覆盖指令写入提示词。

### 5.3 退化禁令

Style 09 的实际提示词必须禁止：

- 中心圆、中心徽章和环形扩散；
- 三行大字、少量口号加大面积空白；
- 等宽卡片阵列、图标墙和逐项配图；
- 粗箭头通用流程；
- 场景、插画或装置替代业务论证；
- 多种视觉媒介混搭。

这些规则是质量底线，不预设具体版式。

## 6. 代码改动范围

仅涉及：

- `scripts/dual_image_overlay/imagegen_handoff.py`
- 对应的提示词编译测试

计划改动：

1. 将完整 `onscreen_judgment + onscreen_text` 编入 `【完整上屏内容】`。
2. 保留 `select_image_locked_text()` 作为重点准确性清单，但不再用于正文取舍。
3. 删除 prompt 中“正文后续进入 PPT 可编辑层”的指令。
4. 自动 `PresentationDecision` 不再渲染到 prompt；显式覆盖仍可渲染。
5. 增加 Style 09 空洞海报退化禁令。
6. 更新诊断规则，使完整正文覆盖率成为提示词门禁。

不修改其他生产文件。

## 7. 测试

### 7.1 单元测试

- P09 类页面的 prompt 同时包含两个重点标签和全部正文要点；
- 长正文不会因 14 字限制被排除出 `【完整上屏内容】`；
- 自动 prompt 不包含 `decision_canvas`、`no_scene` 等内部枚举；
- 显式填写的版式覆盖仍可进入 prompt；
- prompt 不包含“后续 PPT 可编辑文字层承载”；
- Style 09 prompt 包含空洞海报退化禁令；
- 非 Style 09 行为保持不变。

### 7.2 P09–P12 集成检查

- P09：定位、服务对象、分析服务链、支撑能力和不替代边界完整；
- P10：五类能力与协同关系完整；
- P11：首期范围、条件控制和后续扩展完整；
- P12：全部研究任务及决策衔接完整；
- 四页均无自动母题枚举泄漏。

## 8. 完成标准

1. 改动只发生在送图脚本编译链路及测试；
2. 双图法和重建链路没有代码变化；
3. P09–P12 新提示词完整保留获批上屏内容；
4. 自动版式枚举不进入提示词；
5. 相关测试通过；
6. 只先重新生成 P09 供人工确认，通过后再生成 P10–P12。

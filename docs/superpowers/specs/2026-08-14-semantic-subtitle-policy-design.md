# 语义副标题策略设计

## 目标

为 Lightweight Stage 01 增加可解释的副标题策略：仅当内容页的完整主判断较长、而上屏主体应聚焦于流程、架构、对照、矩阵或闭环等信息结构时，生成一个来源受限的短副标题。副标题承载页面判断的压缩表达；上屏模块承载对象、关系和步骤，避免重复堆叠完整判断。

## 非目标

- 不要求每个内容页都有副标题。
- 不修改 Source Truth、语义论证模型或正式作者对提纲和脚本的覆盖权。
- 不把副标题作为对完整主判断的逐字审计锚点。
- 不为任何页面编号、标题或行业领域建立专用规则。

## 适用边界

策略仅考虑 `page_type=content` 的页面，且同时满足以下条件：

1. `core_message` 足够长，完整呈现在上屏会挤压结构阅读；
2. 页面存在结构型视觉意图或表达结构，例如流程、运营闭环、分层架构、双列对照、矩阵、金字塔或双组结构；
3. 可以从 `core_message`、内容单元和上屏模块中保留主体、关系方向、状态和结果，形成独立短语；
4. 压缩结果不引入来源没有表达的因果、承诺、成熟度或时间顺序。

不满足以上条件时策略返回 `not_needed`。定义页、事实清单页、数据证据页和无法安全压缩的判断不生成副标题。

## 数据契约

`outline.json` 的内容页新增 `subtitle_policy`：

```json
{
  "mode": "generated",
  "subtitle": "产品与场景分别在阶段门控下走向运营与复制",
  "rationale": "完整判断较长；双列对照承载两条生命周期，副标题承载共同门控关系。",
  "source_refs": ["ST0077", "ST0078", "ST0079"],
  "derived_from": ["core_message", "onscreen_modules"]
}
```

允许值：

- `generated`：编译器生成的副标题；
- `not_needed`：页面不应生成副标题；
- `author_required`：页面具备副标题条件但无法安全压缩，交由正式作者决定；
- `authored`：正式作者提供的副标题。

正式作者可将 `generated` 改为人工文本，但必须保留 `source_refs` 并将 `mode` 改为 `authored`；不能覆盖人工编辑内容。

## 组件与数据流

新增 `cyberppt/subtitle_policy.py`，职责单一：

1. 接收页面候选的主判断、结构类型、上屏模块、内容单元和来源记录；
2. 判定 `generated`、`not_needed` 或 `author_required`；
3. 从已有语义片段压缩出副标题，并返回来源和理由；
4. 对生成结果执行长度、重复、状态和关系方向的本地校验。

`cyberppt/stage01_compiler.py` 只负责在 `compile_outline_draft()` 构造页面时调用该策略并写入 `subtitle_policy`。它不包含具体文案模板，也不按行业词汇分支。

后续 MD 消费者从页面的 `subtitle_policy.subtitle` 读取副标题。若页面无该字段或模式为 `not_needed`，不输出“副标题”字段。这样 JSON 与 Markdown 在同一编译链路中同步产生。

## 生成准则

副标题优先使用“对象 + 已有关系 + 已有结果/方向”的短语，不复述模块明细：

| 页面关系 | 副标题形态 | 示例 |
|---|---|---|
| 双路径或双生命周期 | 对象分别在共同机制下走向结果 | 产品与场景分别在阶段门控下走向运营与复制 |
| 架构 | 对象通过架构关系支撑目标 | 多层能力与贯穿保障共同支撑服务运营 |
| 闭环 | 对象经闭环实现持续改进 | 运营信息进入评价并驱动产品持续优化 |
| 流程 | 对象沿关键步骤形成结果 | 资源经治理、验证和准入形成可运营服务 |

表格是语义形态，不是固定模板。若输入无法可靠填充，返回 `author_required`。

## 审计策略

在 `script_quality_contract.py` 增加副标题审计，检查：

1. `generated` 副标题不得为空，且脚本文本与 Outline 一致；
2. 副标题的关键主体和关系必须可在 `core_message`、内容单元或允许上屏声明中找到；
3. 副标题不得只重复页面标题或完整主判断；
4. `not_needed` 页面不得把长主判断写成独立“上屏结论”或无归属的总述行来替代副标题；
5. 未能安全压缩的页面使用 `author_required`，审计提示作者而不自动捏造文案。

审计保持“语义等价”而非逐字一致；不改变当前完整文字稿、来源覆盖和模块来源归属的要求。

## 测试与验收

新增定向测试覆盖：

1. 双列对照的两条生命周期生成来源受限副标题；
2. 架构、闭环和流程页均能生成对应关系型副标题；
3. 定义页和普通清单页返回 `not_needed`；
4. 包含风险、条件、待确认、规划等状态的页面不会因压缩升级语气；
5. 无法同时保留主体和关系时返回 `author_required`；
6. MD 编译输出与 JSON 中的副标题完全同步；
7. 人工覆盖副标题不会在重新编译时被覆盖；
8. 副标题审计能拒绝标题复述、来源外关系、长主判断回灌和无归属总述。

验收命令为相关单测与 `PYTHONPATH=. pytest -q`；随后对当前项目仅按需刷新并检查受影响页面，不能重跑上游阶段。

## 风险与控制

- **压缩失真**：只使用已有主判断、模块和来源记录，并在本地策略中保留来源列表。
- **模板化文案**：策略输出 `author_required` 而不是套用弱语义模板。
- **作者成果被改写**：保留现有人工编辑优先级，编译器只补全空缺候选。
- **上屏文字墙回归**：审计把副标题与上屏结构职责分开，拒绝用长判断替代副标题。

# 事实建模性能与可观测性设计

## 目标

在不改变轻量 Stage 01 的语义合同、Source Truth 投影内容、审批节点或 Stage 02 接口的前提下，缩短未变源材料的重复运行时间，并使本地耗时可按阶段复核。

## 非目标

- 不改变 `semantic-argument-model.json`、`source-truth.json` 或既有审计结果的业务语义。
- 不调用模型 API，不把模型/人工作者耗时伪装成本地代码耗时。
- 不新增确认文件、状态 JSON、哈希绑定、attempt 或平行运行目录。
- 不在本阶段实现按章节分块的语义作者输入；该项依赖作者交互契约的独立评审。

## 方案选择

采用“源地图增量复用 + 调用链内快照 + 显式性能报告”方案。

`prepare_source_map()` 仍是唯一的源单元生产者。它根据已登记源文件的相对路径、字节数与 SHA-256 判断文件是否未变；未变文件直接复用既有单元和标题记录，变更或新增文件才执行提取。删除的源文件通过当前 `source/` 枚举自然从新地图中移除。

新增只读的源地图快照对象，集中承载已解析的 registry、heading tree、audit 和 source units。语义输入准备、Source Truth 编译和交叉审计在同一顶层命令链内接收该对象，避免重复读取并逐行反序列化 `source-units.jsonl`。现有公开函数保持兼容：未传快照时仍从权威文件加载。

新增一次运行一份的性能报告，只记录本地阶段的单调时钟耗时、输入规模、复用/提取文件数和运行模式。报告不得包含模型时延、人工时长、提示词全文、源材料正文或新的工作流状态。CLI 在成功或失败时均输出简短摘要；性能报告只作为诊断产物，不能参与审批或影响通过/失败。

## 数据流

```text
source/
  -> source-map fingerprint comparison
  -> reused records + newly extracted records
  -> authoritative source map files
  -> SourceMapSnapshot
  -> semantic authoring input / Source Truth compilation / cross-audit
  -> local performance report
```

## 兼容性与失效规则

- 任一旧源地图文件缺失、格式无效、状态不是 passed，或已有记录无法与当前文件指纹匹配时，安全地退回全量提取。
- 保持既有 stable unit ID 生成规则；对未变文件，复用后的单元、标题及输出顺序必须与全量路径字节等价。
- 变更、添加或删除文件后，输出仍由当前 `source/` 全量集合决定，不能残留已删除文件的记录。
- 性能采集失败不得掩盖正常业务异常；业务成功也不得因仅诊断报告写入失败被误判成功。

## 验收标准

1. 同一项目连续运行两次时，第二次不调用未变文件的提取器，且源地图文件与全量路径一致。
2. 修改一个文件时，仅该文件重新提取；新增和删除文件的地图覆盖正确。
3. 语义准备、Source Truth 编译和交叉审计可消费同一快照，结果与当前文件加载路径等价。
4. 性能报告给出总耗时、各阶段耗时、源文件数、单元数、复用数、重新提取数，且不含源文本。
5. 现有 Stage 01 定向测试和新增的性能/等价性测试均通过。

## 风险与缓解

最大风险是增量缓存生成了陈旧或顺序不稳定的源单元。通过以当前源目录重新排序为权威、严格指纹匹配、无效即全量回退，以及“增量输出与全量输出一致”的测试控制。性能报告仅为诊断数据，绝不进入 gate 或审批判定。

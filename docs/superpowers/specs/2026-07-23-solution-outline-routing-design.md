# 方案型大纲路由与结构审计设计

## 背景

CyberPPT 当前把 MBB 证据表、内容脑暴和 SCR 设为第一阶段默认路径。该默认值会把研究方案、建设方案、实施方案、立项材料及政府、央国企内部汇报错误地改写为咨询型表达，进而出现以下问题：

- 沿用咨询式结论先行或 SCR，而没有保留正式方案材料的工作顺序；
- 把封面、目录、章节页、封底从完整页面序列中抽离，破坏章节转场与论述推进；
- 混用页面标题和页面主判断，把长判断句直接当作标题；
- 按源材料小节或清单项机械拆页，造成页面数量失控和论证碎片化；
- 为控制总页数过度压缩主体建设内容，或因“不限页数”无限拆页；
- 让方法性原则占据独立核心页面，而源材料主体内容被压缩。

## 目标

建立“材料类型路由—结构化大纲合同—确定性审计—换方向重试”的第一阶段规划机制。方案型架构是默认路径；咨询型架构仅在用户明确要求或材料类型明确匹配时启用。审计失败必须推动重写，不得直接放弃任务。

## 非目标

- 不在仓库中内置或模拟大模型执行器。
- 不替代证据表、来源追溯、信息密度和视觉规划门禁。
- 不用固定页数替代内容判断。
- 不强制所有正式材料沿用源文档原始目录；当源结构确实混乱时允许在保留业务顺序的前提下重组。

## 双路由

### `solution`：默认

适用于研究方案、建设方案、实施方案、前期研究、立项材料、可研材料，以及政府、协会、央国企内部讨论或正式汇报。

默认顺序由材料角色决定，典型结构为：

1. 现状基础与形势需求；
2. 总体定位、目标与边界；
3. 主要建设内容与应用安排；
4. 实施路径、投入、风险与保障；
5. 研究判断、决策条件与下一步。

源材料已有清晰正式结构时，优先沿用、归并和优化。页面标题简洁标识讨论对象；页面主判断单独记录，不默认把判断句变成长标题。

### `consulting`：显式启用

仅在以下任一条件满足时启用：

- 用户明确要求咨询风格、SCR、金字塔或结论先行；
- 材料类型明确属于市场研究、竞争分析、战略选择或经营诊断，且不存在更高优先级的正式方案结构。

MBB 证据表可继续作为后台证据管理方法，但不得反向决定方案型材料的章节结构和前台表达。

## 结构化大纲合同

大纲使用 JSON 表达，顶层至少包含：

- `schema`: 固定为 `cyberppt.outline.v1`；
- `material_type`: 识别出的材料类型；
- `audience`: 汇报对象；
- `architecture_mode`: `solution` 或 `consulting`；
- `architecture_reason`: 路由依据；
- `source_section_weights`: 源材料各主体章节的信息权重；
- `pages`: 按最终放映顺序排列的完整页面数组；
- `retry`: 当前尝试次数、最大次数、上一轮错误码和本轮策略。

每一页至少包含：

- `page_id` 和 `sequence`；
- `page_type`: `cover`、`contents`、`chapter`、`content` 或 `closing`；
- `chapter_id`；
- `title`；
- `main_message`；
- `source_refs`；
- `business_question`；
- `visual_center`；
- `modules`；
- `source_weight`。

模板页与内容页使用同一 `pages` 数组。章节页只允许章节编号和章节名称，`main_message`、`business_question`、`visual_center` 和 `modules` 必须为空。

## 审计规则

以下规则失败时返回错误码、证据位置、重写策略和可否继续重试：

| 错误码 | 失败条件 | 下一轮策略 |
|---|---|---|
| `SOLUTION_ARCHITECTURE_REQUIRED` | 方案类材料使用 `consulting`，且用户未显式要求 | 切换到方案型架构并恢复材料工作顺序 |
| `TEMPLATE_PAGES_DETACHED` | 模板页不在完整连续页面序列，或章节页不位于所属正文前 | 重建单一连续页面数组 |
| `CHAPTER_PAGE_HAS_CONTENT` | 章节页承载正文论点、模块或视觉中心 | 清空章节页正文并移至后续内容页 |
| `TITLE_CLAIM_COLLAPSED` | 标题与主判断相同，或标题明显为长判断句 | 生成简洁主题标题并保留独立主判断 |
| `ATOMIC_SECTION_SPLIT` | 多个相邻页面仅对应同级清单项，业务问题与视觉中心高度重复 | 按完整业务问题聚合页面 |
| `PAGE_COUNT_PRECOMMITTED` | 以固定页数驱动压缩或扩张，且没有密度证据 | 解除页数目标，按业务问题和密度重新规划 |
| `SOURCE_WEIGHT_DISTORTED` | 主体章节页面权重显著低于源材料，方法性或辅助内容被放大 | 按源材料信息权重重新分配页面 |
| `METHOD_PAGE_OVERPROMOTED` | 方法性原则单独成页，但没有独立业务结论和证据 | 合并进相应业务页面作为模块 |
| `CHAPTER_FLOW_BROKEN` | 章节之间没有前后依赖或章节正文偏离章节使命 | 按方案工作顺序重排章节和页面 |

第一版审计采用确定性、可测试的启发式规则。无法可靠自动判断的语义项输出结构化证据，交由生成代理重写和人工复核，不用伪精确分数掩盖不确定性。

## 换方向重试协议

- 默认最多尝试 3 次；项目可在 1—5 次范围内显式配置。
- 每次失败写入审计报告，记录错误码、页码、证据、上一策略和下一策略。
- 下一次提交必须增加尝试编号，并声明采用的策略；相同输入原样重跑直接失败。
- 只要仍有剩余次数，命令返回“需要重写”状态和机器可读的 `retry_directive`。
- 达到上限后不放弃任务，生成升级报告，列出未解决冲突及 2—3 个可选调整方向，等待用户决策。
- 仓库不内置模型执行器；生成代理负责按 `retry_directive` 重写大纲并再次调用审计。

## CLI 与产物

新增命令：

```text
python -m cyberppt outline-audit <project> --input <outline.json> [--max-attempts 3]
```

产物写入：

- `workbench/stages/01-analysis/outline-contract.json`：最近一次提交的大纲合同；
- `workbench/stages/01-analysis/outline-audit.json`：最近一次审计结果；
- `workbench/stages/01-analysis/outline-attempts/attempt-NN.json`：每轮输入与结果；
- `workbench/stages/01-analysis/outline-escalation.json`：达到重试上限时的升级报告。

CLI 退出码：

- `0`：审计通过；
- `2`：输入或项目错误；
- `4`：审计失败且应按指令重写；
- `5`：达到重试上限，需要用户决策。

## 文档合同变更

- `SKILL.md`：第一阶段默认从 SCR 改为材料类型路由；方案型路径优先；咨询路径显式启用。
- `references/source-analysis.md`：证据分析保持后台中立，不再强制所有材料进入 MBB/SCR 前台结构。
- `references/storyline.md`：拆分方案型与咨询型规划协议，并加入完整页面序列、模板页、标题/主判断和聚合拆页规则。
- 项目 README：说明大纲审计和重试产物位置。

## 测试策略

单元测试覆盖：

- 方案材料默认路由到 `solution`；
- 用户显式要求时允许 `consulting`；
- 模板页嵌入连续序列并正确约束章节页；
- 标题与主判断区分；
- 同级清单机械拆页被识别；
- 主体章节权重失真和方法页过度提升被识别；
- 失败返回可执行重写策略；
- 三次失败生成升级报告而非终止任务；
- CLI 退出码和产物路径稳定。

文档合同测试覆盖 `SKILL.md` 和 reference 中的默认路由、方案型架构、咨询型显式启用及有限重试约束。

## 验收标准

1. 正式方案材料在无用户覆盖时不能通过咨询型大纲审计。
2. 完整页面序列同时包含模板页和内容页，章节页不能承载正文。
3. 审计能识别本轮对话暴露的五类结构问题，并返回不同的重写策略。
4. 失败不会直接结束任务；重试耗尽后提供升级报告和可选方向。
5. 新增测试通过，现有 CLI、脚本门禁和 PPTX 生产测试不回归。

# 自然语言入口说明

## 目标

让使用者把 CyberPPT-Script 当成“PPT 脚本专用 Agent”，而不是一个需要学习工作流的工程工具。

用户描述任务即可，Agent 负责识别流程、当前状态和下一步动作。

## 最常用的四句话

### 1. 新建脚本

> 根据这个 Word 生成 PPT 脚本。

Agent 自动完成材料理解、整套核心论点、章节故事线、逐页问题—答案—证明链和重要内容覆盖检查，并默认先给出“脚本规划待确认”。

### 2. 继续生成

> 继续。

如果当前规划已经待确认，Agent 直接进入整套脚本写作、内部审稿和重写，最终生成 `dist/final-script.md`。

### 3. 修改单页

> 第 8 页写得不好，重新写。

Agent 自动读取第 8 页、前后页、规划和相关源材料证据，只改需要调整的内容，并保持整套逻辑连续。

### 4. 整体优化

> 整套脚本再检查一遍，重点看重复、遗漏和逻辑。

Agent 自动进行整套审阅和重写，不向用户输出内部 Critic 对话。

## 其他自然表达

以下说法都应自动识别：

- `把这些材料整理成一套汇报 PPT 脚本。`
- `做 20 页左右。`
- `先给我看看整体怎么讲。`
- `这个提纲不行，重新规划。`
- `把第 6、7 页合并。`
- `第 12 页信息太多，拆开。`
- `上屏文字太密，压缩一下。`
- `按刚才的意见继续。`
- `不用停，直接把完整脚本做出来。`

## 默认交互规则

### 新建任务

默认只停一次：脚本规划确认。

```text
源材料
  ↓
自动理解
  ↓
自动规划
  ↓
【脚本规划待确认】
  ↓ 用户说“继续”
自动整套写作
  ↓
内部 Critic + Rewrite
  ↓
【最终脚本已生成】
```

### 用户要求“一次完成”

若用户说“直接生成”“不用停”“一次完成”等，规划仍然在内部完成，但不单独要求确认。

### 修改已有脚本

优先识别修改范围：

- 指定页 → 定向页面修改；
- 指定章节 → 章节级重写；
- 整体逻辑 → 全稿 Critic + Rewrite；
- 重新提纲 → 回到整套规划。

## 不应出现的交互

除非用户主动询问，Agent 不应要求用户：

- 选择 UNDERSTAND / PLAN / AUTHOR；
- 指定 Skill 名称；
- 阅读 JSON Schema；
- 运行 CLI；
- 手工维护 foundation / plan 状态；
- 阅读 Critic、Rewrite 或审计过程。

## 最终内容洁净度

最终 `dist/final-script.md` 只面向 PPT 使用者和听众，不得混入：

- Agent 自我对话；
- “我接下来将……”等过程说明；
- 审稿意见；
- 修改理由；
- 工具与模型说明；
- 兼容性备注；
- 内部状态和字段解释。

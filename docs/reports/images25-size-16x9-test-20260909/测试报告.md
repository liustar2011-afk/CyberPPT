## 测试方法

沿用上一轮正式 Stage 02 P04 提示词、palette-09 参考图和现有 OAuth 生图适配器。请求模型 gpt-image-2.5-sunburst，quality=high，postprocess=False。仅修改请求尺寸及提示词中的尺寸、比例约束，并去除禁止 16:9 输出的冲突句。三次均使用 images 路径完成，无 Responses 回退。每种尺寸一次调用，无本地缩放或增强。

三张原图均已验证可解码，且输出副本与 raw 文件哈希一致；已逐张目视查看。此为隔离接口诊断，未执行正式中文审计、语义验收或 PPTX 生产，图片仅供诊断。实际后端模型版本未捕获。

## 跨轮观察

- 本轮 16:9 请求：1672×941，共 1,573,352 像素，比例约 1.7768，与 16:9 接近。
- 上轮 2:1 请求：1774×887，共 1,573,538 像素，比例为 2:1。
- 两组像素数均约 157 万，差异仅 186 像素。当前 high 质量、带参考图的调用结果与固定像素档位的表现相符；这属于推断，尚无后端策略证明。
- 提高请求分辨率未获得更多原生像素。不能据此断言其他质量档位、无参考图调用或公开 API 具有相同上限。单次调用耗时不能作为性能统计结论。

# Onscreen Copy Authoring

## Purpose

Translate complete argumentation into presentation language without losing the page's decision logic.

## Order of work

Write in this order:

1. complete argument;
2. page hierarchy;
3. onscreen copy;
4. speaker notes.

Do not start by compressing the source into short phrases.

## Onscreen hierarchy

A content page normally uses:

- page title;
- optional lead sentence when it materially improves comprehension;
- a small number of semantic groups;
- within each group, a short business heading and differentiated supporting copy;
- numbers, labels, annotations, or boundary notes only when needed.

## Compression rules

- Preserve the claim, object, action, qualifier, and result that carry meaning.
- Shared predicates or qualifiers should appear once at the parent level when possible.
- Child items should carry differentiated information.
- Avoid mechanically converting every source bullet into one visual module.
- Avoid turning background details, form fields, attachment lists, or operational minutiae into equal-weight onscreen blocks.
- Numerical ordering may be used only when the source supports real sequence, phase, priority, timing, dependency, or gating.

## Language quality

Prefer concrete institutional and business wording. Generic verbs such as “加强、提升、推动、赋能、打造、构建” require a concrete object and mechanism; remove them when they add no information.

Titles, module headings, and short labels should be concise, but compression must not delete essential boundaries, responsibilities, conditions, or distinctions.

## Renderer independence

Do not specify font, color, icon style, decorative treatment, image-generation model, or visual-style preset in the final script. Those belong to Stage 02.

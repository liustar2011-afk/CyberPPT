# 页面语义适配审计

## 审计结论

本轮已完成语义基础与 Deck Plan 的系统性返工。来源目录、八章顺序和章节职责保持不变；166 条来源记录现展开为 274 个语义单元，其中 33 条复合记录已拆分不同谓词、职责和事件状态。修订后的 Deck Plan 已通过结构校验和来源忠实审计，结果为 0 个错误、0 个警告。规划已获确认，并已据此完成 AUTHOR、Critic、重写和最终交付。

## 根因复核

| 环节 | 初稿机制缺陷 | 本轮修复 |
|---|---|---|
| 语义理解 | 一条归一化事实固定生成一个语义单元，逗号连接的多职责内容无法拆开 | 投影器支持上游编写的 `semantic_units`，编译器原样保留语义角色、事件状态和保护术语 |
| 页面规划 | 先形成模块标签，再用空泛理由把证据挂到标签下 | 每页先声明业务问题，每个模块再声明子问题、来源职责和排除边界 |
| 证据质询 | “直接回答当前页面问题”等循环论证可以通过审计 | 新增 `EVIDENCE_FIT_REASON_GENERIC` 阻断规则，要求理由出现来源特有命题及其页面职责 |
| 语义消费 | 记录级锚点只能证明一个便利片段被使用，无法保证复合事实内部内容完整 | 274 个语义单元逐一声明 `full_copy` 或 `trace_only` 归宿，后续 AUTHOR 按单元检查 |
| 页面关系 | 标签之间的顺序、层级或映射缺少业务问题约束 | 页面关系与模块问题同步重审；P04 使用任务展开顺序，P16 使用能力映射矩阵，阶段安排使用时间顺序 |

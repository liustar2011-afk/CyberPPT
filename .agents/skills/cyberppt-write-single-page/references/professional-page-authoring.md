# 专业单页创作方法

## 一、页面的本质

专业内容页不是事实容器，也不是视觉版式。它是整套演示中的最小叙事与论证单元：从前页接收一个上下文，围绕一个受众问题形成可验证命题，用有职责的证据和明确关系完成论证，再向后页交付一个结论或新问题。

页面成立需要同时满足五件事：

1. 有清晰的叙事角色；
2. 有可判断、可证明的页面命题；
3. 有一条支配阅读顺序的主论证链；
4. 有与业务关系相符的信息架构和视觉语法；
5. 各文字层各司其职，并保持来源忠实。

“一页一个主题”只是最低要求。真正的标准是本页有不可被相邻页替代的新增价值。

## 二、叙事角色与页间承接

常见叙事角色包括：提出背景、界定问题、解释变化、建立必要性、说明机制、拆解架构、定义职责、展示场景、比较方案、给出路径、明确门控和形成收束。角色描述应说明本页在论证中的作用，不能只写“介绍某某”。

逐项回答：

- 上一页已经让受众知道了什么？
- 当前仍悬而未决的关键问题是什么？
- 本页新增什么判断、关系或机制？
- 如果删除本页，叙事链会缺失什么？
- 下一页以本页哪个结论为前提？

出现以下任一情况，应优先修正 Outline 或页面划分：

- 本页同时回答两个互不依赖的问题；
- 页面主要内容在前页已经完整出现；
- 页面核心结论实际属于后页；
- 不借助标题无法说明本页与相邻页的区别；
- 前页没有提供本页所需前提，或本页没有为后页提供必要输入。

## 三、页面命题

页面命题是受众读完后能够复述的一句可判断陈述。理想命题通常包含业务对象或主体、关键动作或关系、条件或状态，以及该页要建立的判断。

命题应通过五项测试：

- `specific`：不是“提升能力、创造价值”之类空泛口号；
- `decidable`：能够判断成立与否，不只是一个名词主题；
- `provable`：本页来源证据能够直接支撑；
- `bounded`：保留“已、正、拟、可、在……条件下”等原始状态；
- `exclusive`：不抢写下一页，也不重复上一页结论。

标题不等于命题。标题负责界定页面主题和观察角度，命题负责给出本页要成立的判断。来源只支持描述时，标题和命题都不得升级为承诺或结论。

## 四、主论证链

一页可以包含多种局部关系，但只能有一条主论证链控制阅读顺序。主链至少包含：

`页面命题 → 核心证据 → 关系解释 → 页面落点 → 适用边界`

不是所有页面都要写成“因此”。架构页的落点可能是构成关系，职责页可能是协同界面，流程页可能是阶段门控。所谓闭环，是受众能够从证据沿正确关系走到命题，而不是强行添加结论连接词。

判断论证是否成立：

- 移除任一核心证据后，命题是否仍被充分支持；
- 每个模块是否承担不同论证职责，而不是换词重复；
- 关系是来源已有事实，还是作者自行推导；
- 页面落点是否回答了受众问题；
- 边界是否阻止结论被扩大到来源没有覆盖的范围。

## 五、证据提炼

来源全覆盖不等于所有事实平均上屏。先按论证职责分配证据：

| 证据职责 | 页面作用 | 一般呈现层 |
|---|---|---|
| claim | 直接证明页面命题 | 完整稿和上屏 |
| reason | 解释原因、机制或关系 | 完整稿，必要时上屏 |
| instance | 提供对象、场景、数字或实例 | 完整稿或上屏细项 |
| boundary | 保留条件、状态、责任和适用范围 | 完整稿；影响判断时必须上屏 |
| trace_only | 支持来源追溯但不承担受众理解 | 证据映射 |
| metadata | 题名、作者、日期、目录、章节标题 | 不进入内容页正文 |

提炼不等于泛化。至少保留能够识别该业务的来源特征，如专有对象、主体、动作、处理对象、条件、状态、数字或场景。用“能力、机制、价值、保障”替换这些特征，会让页面看似简洁却失去信息。

## 六、信息架构

信息架构是论证在页面上的层级化组织。先确定：

- `entry`：受众从哪里进入；
- `center`：页面视觉与逻辑中心；
- `axis`：支配阅读的主轴；
- `nodes`：承担命题、证据、关系或边界的节点；
- `links`：节点之间的业务关系；
- `sequence`：阅读顺序；
- `exit`：页面最终落点及向下一页的接口。

同层节点必须使用同一分类维度。若三个模块分别是“主体、能力、价值”，它们通常不能直接并列；应先明确它们是阶段链、因果链还是不同层级，再组织结构。

长明细不得机械截句。先用一个来源具体、能够独立概括该组信息的业务小标题承接，再在其下保留完整明细句。该层级只允许两种真实关系：分类—成员，或概括—展开；不能用缩进把属性、变化、需求、原因、结果和应对伪装成同层并列。以“随着、通过、根据、围绕、面向”等开头的结构必须与其主句共同出现，不能放在“驱动背景：”“实现方式：”之类标签后成为残句。

信息密度由论证需要决定，不用固定卡片数或字数代替编辑判断。内容过多时，依次考虑：消除重复、合并同职责证据、把实例降为细项、把追溯信息移出阅读层；不得先删除业务关键事项。

## 七、文字层次的专业分工

### 标题

页面标题由已验证 Outline 锁定，单页作者不得改写。默认保留源材料标题及顺序；仅因单页容量拆页时，可使用“源标题（一）”“源标题（二）”。如标题确需改变，先修订权威 Outline 并重新验证。标题保持政府公文式、平实、严谨、可识别，不新增口号、悬空判断、泛化表述或来源未支持的承诺。

### 核心结论

用一句可验证命题控制整页，不重复标题，不堆砌所有细节。来源只允许描述时，可以使用“页面判断”而不是强结论。

核心结论不是只供作者和审计使用的后台字段。先判断它是否包含受众理解本页不可缺少的判断；若包含，必须进入受众可见层，但呈现形式由本页论证关系决定：判断—证据页可使用独立结论，流程或机制页可作为正文导语，架构或构成页可融入承担关系的核心模块，递进或交付页可作为结果收束。不得为了格式统一把每页都固定成“标题下一句话”，也不得让标题、导语、模块和收束语重复同一判断。

仅当核心结论只是作者对多个可见模块的后台归纳、可见关系已经完整表达同一判断，或直接上屏会造成来源未支持的状态升级时，才可不直接呈现；此时应在文字稿取舍说明中写明理由。不得把有业务价值的核心结论长期留在“主判断”字段而不被受众使用。

### 完整文字稿

完整稿应是一段可供编辑和讲解使用的完整论证：语言自然，段落按语义职责组织，事实与解释分明。它不是来源原文拼接、页面元素清单、主持词或审计锚点仓库。

### 上屏文字

上屏是完整论证的结构化压缩，不是摘要，也不是关键词墙。它应保留：页面命题、关键业务对象、关系方向、必要边界和页面落点。每个模块应能独立表达一个完整信息单元，模块之间共同回答页面问题。

### 视觉结构

视觉结构把业务关系转换为空间关系。它描述语义节点与连接，不只是“左边一张图、右边三张卡”。视觉中心、主轴和阅读顺序应与主论证链一致。

### 演讲者备注

备注补充证据、条件、例子和页间过渡。不能用备注补救上屏遗漏的核心事实，也不记录制作或审计过程。

### 证据映射

证据映射证明来源消费与角色分配，只服务追溯和复核，不进入受众阅读层。

## 八、专业重写顺序

重做问题页时依次处理：

1. 用一句话复原当前页面实际在说什么；
2. 对照 Outline 和相邻页判断页面使命是否成立；
3. 重写页面命题和不可替代价值；
4. 选择主论证原型并重排证据职责；
5. 先重写完整稿，再重建上屏层级；
6. 选择与关系匹配的视觉语法；
7. 最后处理标题、字数、格式和审计问题。

如果只修改措辞而不改变错误的命题、论证或层级，不能称为重做。

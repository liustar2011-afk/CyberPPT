# 单页脚本契约、评分与检查

## 使用原则

优先保持当前项目权威脚本的字段名称和排版形式。以下模板用于没有现成权威页面，或需要在对话中完整展示专业设计依据时；不要为了套模板建立平行稿件。

## 专业内容页模板

```markdown
## 第X页：页面标题
- 页面类型：内容页
- 叙事角色：本页在整套叙事中承担的作用
- 承接上页：从上一页接收的事实、问题或判断
- 受众问题：本页独立回答的一个关键问题
- 页面命题：来源支持、状态准确、可判断的单句命题
- 交付下页：向下一页交付的结论或待解问题
- 不可替代价值：删除本页后叙事链缺失的内容
- 主论证原型：判断—证据 / 需求—供给缺口—必要性 / 其他
- 主论证链：证据A + 证据B → 关系解释 → 页面命题
- 决策边界：条件、状态、责任和禁止越界内容
- 证据：ST0001、ST0002
- 边界依据：ST0003
- 证据映射：claim→ST0001；reason→ST0002；boundary→ST0003
- 完整文字稿：

按页面论证需要组织若干语义段。先建立命题，再展开事实和关系，形成页面落点并保留边界。

- 文字稿取舍说明：
  必留上屏：页面命题、关键对象、关系、数字或业务特征
  仅讲解：支撑理解但不适合占据屏幕的事实、例子和必要边界
  仅追溯：ST0004、ST0005
- 上屏文字：
  核心结论：可独立阅读的页面命题
  模块一：承担第一项论证职责的完整业务短语
    细项：对象、动作、条件、数字或状态
  模块二：承担第二项论证职责的完整业务短语
    细项：来源特征和关系落点
- 上屏模块清单：["核心结论", "模块一", "细项", "模块二", "细项"]
- 上屏顶层模块清单：["核心结论", "模块一", "模块二"]
- 视觉意图类型：与论证关系匹配的正式类型
- 视觉证明：视觉结构如何帮助受众沿证据到达页面命题
【视觉结构，不上屏】
入口、视觉中心、主轴、节点、连接关系、阅读顺序和出口。
【演讲者备注】
展开关键证据、条件与边界，并完成向下一页的自然过渡。
```

`上屏模块清单` 和 `上屏顶层模块清单` 不是可选的说明性字段。`script-audit` 不会从缩进或空行去推断模块层级——它只信这两个显式声明的 JSON 数组：`上屏顶层模块清单` 决定 `ONSCREEN_MODULE_COUNT_MISMATCH`（顶层模块数是否匹配所选表达形式）和 `PATH_ORDER_SIGNAL_MISSING`（路径类视觉是否需要显式顺序信号）等检查的判定对象。没有这两个字段，即使正文缩进层级写得再清楚，审计也可能把整页识别成一个扁平模块。路径类、阶段类视觉意图（例如"双侧对照后汇聚到缺口""阶段—门控—决策"）还需要在上屏文字里加 `①②③` 编号或 `→` 箭头作为顺序信号。

**已验证可通过审计的完整样例**：`projects/power-data-infrastructure-cooperation-v12-20260807/outputs/batches/*/script-final_cyberppt_deliverable_*.md`（例如 `style09-ca7-baseline-p22-*` 目录下的 P22 页）。这些文件走完了从脚本到出图的全流程，格式已被 `script-audit` 验证过，比本文件的模板更可靠；新页面遇到格式类报错时，可以对照这些真实样例学习**字段结构和格式写法**（如 `上屏模块清单`、编号顺序信号的具体写法），但仍须遵守"只消费当前项目事实源"的边界——不得挪用其业务内容、判断或证据编号，只能借鉴其排版和字段用法。

## 已知限制（写作前应了解）

以下几类规则组合目前没有任何写法能同时满足，遇到时不要继续在文案上反复试错，按下列方式处理并如实记录：

- **锚点覆盖 vs 上屏明细长度上限**：当 `outline.json` 里某个 `content_units[].onscreen_anchors` 超过约 30 字时，逐字保留该锚点必然触发 `ONSCREEN_DETAIL_PHRASE_TOO_LONG`（严格模式下为 error）；而如果为了控制长度改写锚点原文，又会触发 `ONSCREEN_CONTENT_UNIT_GAP`。两者只能取其一，优先保锚点覆盖（内容不失真优先于格式达标），并在 `文字稿取舍说明` 里注明"锚点原文超长、按内容忠实优先保留"。
- **锚点覆盖 vs 语义并列一致性**：为了让缩进子项通过 `_semantic_line_role` 的同角色判定而改写用词，可能连带破坏该行原本承载的锚点原文，反过来触发 `ONSCREEN_CONTENT_UNIT_GAP`。同样优先保锚点覆盖。
- 这两类冲突已向仓库维护者报告，根治需要给"已证明锚点覆盖达标"的行豁免长度和语义一致性检查，而不是作者在文案上无限重试。

## 专业质量评分（100分）

硬阻断检查通过后再评分：

| 维度 | 分值 | 高分标准 |
|---|---:|---|
| 页面战略角色与相邻页承接 | 15 | 输入、输出和不可替代价值清楚，无重叠或断裂 |
| 页面命题清晰度 | 15 | 命题具体、可判断、可证明、状态准确且不越界 |
| 论证闭环与关系正确性 | 20 | 一条主链贯穿证据、关系、命题和边界，无伪因果 |
| 来源提炼与业务特征保留 | 15 | 证据职责明确，保留关键主体、对象、动作、条件、状态和数字 |
| 信息架构和层级 | 15 | 同层同维、主次分明、阅读顺序明确、密度合理 |
| 上屏独立可读性 | 10 | 脱离讲解仍能回答页面问题，不是标签或摘要堆积 |
| 视觉语法匹配 | 5 | 空间关系准确表达业务关系，视觉中心与命题一致 |
| 文体、标题与格式完成度 | 5 | 平实严谨、语言自然、层次与字段完整 |

评分解释：

- `90–100`：可提交正式人工门；
- `80–89`：基本可用，但需编辑后提交；
- `70–79`：存在结构性问题，需要重写；
- `<70`：页面使命、命题或上游契约需要重建。

不得用总分掩盖硬阻断。来源漂移、关系写反、状态升级、重要事项遗漏、越界或抢写后页内容时，一律判定不可提交。

## 人工检查表

### 页面成立

- [ ] 页面具有明确叙事角色、输入、输出和不可替代价值。
- [ ] 只回答一个独立受众问题。
- [ ] 页面命题具体、可判断、可证明且保持来源状态。
- [ ] 主论证链能够用一句关系链完整复述。
- [ ] 相邻页没有重复、断裂或抢写。

### 来源与论证

- [ ] 主体、动作、对象、条件、状态、数字和专有业务词均可追溯。
- [ ] 核心证据分别承担 claim、reason、instance 或 boundary 职责。
- [ ] 没有把并列、共现、构成、缺口或条件误写成因果。
- [ ] 没有把元数据写进内容页正文。
- [ ] 重要事项未经用户明确决定没有舍弃。

### 信息与文字

- [ ] 标题、页面命题、上屏结论和视觉中心指向同一主题。
- [ ] 有受众价值的主判断已按论证关系转化为独立结论、正文导语、关系模块或结果收束；未机械固定位置，也未只留在后台字段。
- [ ] 完整稿是自然完整的论证，不是原文拼接、讲稿口语或审计占位句。
- [ ] 上屏保留关键业务特征、关系方向和必要边界。
- [ ] 同层模块属于同一维度，层级和阅读顺序清楚。
- [ ] 较长明细使用“业务小标题—完整明细句”，二者为真实概括—展开关系；没有截断状语或伪造并列。
- [ ] 演讲者备注没有补救上屏缺失的核心事实。

### 视觉与验证

- [ ] 视觉结构明确入口、中心、主轴、节点、连接、顺序和出口。
- [ ] 流程、矩阵、分层、闭环或协同结构具备相应语义条件。
- [ ] 目标页正式稿的 `script-audit --lightweight` 已运行。
- [ ] 审计通过后再次完成专业人工阅读和评分。

## 审计问题处理

| 现象 | 根因倾向 | 禁止处理 | 正确处理 |
|---|---|---|---|
| 正文出现题名、作者、日期、目录 | 元数据角色错误 | 强行串入完整稿 | 修正角色和页面归属 |
| 当前问题被标为条件成熟后事项 | Source Truth 状态不相容 | 在正文中弱化或模糊 | 对照原始语态修正状态 |
| 需求增长被写成支持稳定供给 | Outline 关系方向错误 | 用视觉文案掩盖 | 修正 content relation |
| 审计要求字面锚点但正文已覆盖语义 | 锚点或检查器问题 | 追加审计占位句 | 修正锚点或检查逻辑 |
| 来源词触发范围检查 | 检查器误报或页面边界不准 | 换成空泛近义词 | 保留来源词并修正根因 |
| 字数达标但出现断词或标签墙 | 机械压缩 | 继续删字换取通过 | 重建信息层级和业务短语 |

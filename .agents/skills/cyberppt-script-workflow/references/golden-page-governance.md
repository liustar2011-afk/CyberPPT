# 黄金页面 08：Governance / Boundary

> 教学定位：展示 `governance chain`。主体必须与责任绑定，控制机制必须说明控制对象，并落到可验证的受保护结果。

## 页面使命

说明统一预测运行中业务、数据和分析责任如何通过会商审校、发布授权和复盘留痕形成可追溯治理闭环。

## 核心结论

业务口径、数据版本和分析方法分别落实责任主体，并通过会商审校、发布授权和复盘留痕机制共同保护预测结论的一致性、可追溯性与可复核性。

## 主论证链

`业务/数据/分析责任主体 → 各自责任对象 → 共同控制机制 → 一致、可追溯、可复核的预测结论`

## Argument Topology

`governance chain`

页面先建立三条“主体—责任对象”责任线，再汇入共同控制层，最终落到受保护结果。角色之间可协同，但责任边界不能互相替代；共同控制机制承担跨主体治理，不作为第四个责任主体。

## Relation Contract

- Node Role：并行责任主体、各自责任对象、共同控制机制、受保护结果。
- Edge Semantics：主体对责任对象承担明确责任；共同控制机制对关键判断和变更实施控制；控制最终落到可验证结果。
- Direction / Cardinality：`Actor → Responsibility Object → Control Mechanism → Protected Outcome`；多个 Actor / Responsibility Object 可汇入共同控制层。
- Invariant：Control Mechanism 不能与 Actor 变成同层第四主体；每个主体必须先绑定自己的责任对象，再进入共同治理层。
- Confusable With：Parallel。
- Disambiguation Rule：Governance 回答“谁对什么负责、通过什么控制保护什么结果”；Parallel 只回答“结论由哪些同层维度构成”。

## Relation Units

1. 业务牵头方 → 指标口径、判断尺度和结论边界；
2. 数据责任方 → 数据来源、质量校验和版本记录；
3. 分析执行方 → 模型方法、情景假设和计算过程。

## 共同控制机制

- 会商审校：核对关键结论与共同口径，处理跨主体判断差异；
- 发布授权：控制正式成果版本、发布范围和变更责任；
- 复盘留痕：记录偏差原因、责任判断及后续规则参数调整。

## 受保护结果

- 结论口径一致；
- 数据来源可追溯；
- 分析过程可复核；
- 版本变更有记录。

## 完整文字稿

统一预测要持续运行，需要把业务口径、数据版本和分析方法分别绑定到明确责任主体。业务牵头方负责指标定义、判断尺度和结论适用边界，确保不同周期围绕同一业务问题形成判断；数据责任方负责来源登记、质量校验和版本管理，确保输入能够追溯；分析执行方负责模型方法、情景假设和计算过程，保证结果可解释、可复核。

三条责任线在共同控制层汇合。会商审校负责核对关键结论与共同口径，发布授权负责控制正式成果版本、发布范围和变更责任，复盘留痕负责记录偏差原因及后续规则参数调整。治理结果直接落到四项可检查状态：结论口径一致、数据来源可追溯、分析过程可复核、版本变更有记录。

## 上屏文字

- 明确业务、数据和分析责任，以共同治理机制保护预测结论的一致性、可追溯性与可复核性
  - 主体｜业务牵头方
    - 责任对象｜指标口径、判断尺度、结论边界
  - 主体｜数据责任方
    - 责任对象｜数据来源、质量状态、版本记录
  - 主体｜分析执行方
    - 责任对象｜模型方法、情景假设、计算过程
  - 共同控制机制
    - 会商审校｜控制关键结论与共同口径一致
    - 发布授权｜控制正式版本、发布范围和变更责任
    - 复盘留痕｜控制偏差原因及规则参数调整可追溯
  - 受保护结果｜结论口径一致｜来源可追溯｜过程可复核｜变更有记录

## 视觉结构

页面采用“责任线汇聚治理层”的单一结构。上游为三条并行责任线：业务牵头方、数据责任方、分析执行方分别与自己的责任对象绑定；三条责任线共同汇入会商审校、发布授权、复盘留痕组成的控制层；控制层再连接到“结论口径一致、来源可追溯、过程可复核、变更有记录”的受保护结果。主体、责任对象、控制机制和结果四类节点必须在视觉角色上清晰区分，共同控制层不得与三个责任主体画成四张同级卡片。

## 演讲者备注

Governance 是否成立，先检查责任是否“绑定到对象”，再检查控制是否“跨主体生效”。主体名称本身不构成治理语义；只有业务、数据、分析三个 Actor 分别对明确责任对象承担责任，责任线才成立。责任对象也不能被共同控制层吞并，否则责任主体会失去可追溯边界。

共同控制机制承担的是跨主体判断、正式发布和复盘变更的控制，不承担三个 Actor 的日常责任。治理有效性最终应落到可检查结果：口径是否一致、来源能否追溯、过程能否复核、变更是否留痕。若页面只列组织和制度名称，却没有责任对象与受保护结果，应判定为治理关系不完整。

## 作者自检

1. 上屏统一采用“主体｜Actor / 责任对象｜Object / 共同控制机制 / 受保护结果｜Outcome”的微语法。
2. 三个责任主体均与明确责任对象绑定，主体名称不会单独悬空。
3. 三条责任线处于同一 Actor 层级，责任边界互不替代。
4. 会商审校、发布授权、复盘留痕处于共同控制层，不与三个 Actor 并列为第四主体。
5. 每项控制机制都说明控制对象和控制动作。
6. 最终结果具体到一致性、可追溯、可复核和变更记录，可直接检查。
7. 上屏纯文本可恢复 `Actor → Responsibility Object → Control Mechanism → Protected Outcome`。

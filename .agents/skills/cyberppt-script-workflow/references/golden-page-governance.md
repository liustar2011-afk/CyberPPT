# 黄金页面 08：Governance / Boundary

> 教学定位：展示 `governance chain`。主体必须与责任绑定，控制机制必须说明控制对象，并落到可验证的受保护结果。

## 页面使命

说明统一预测运行中业务、数据和分析责任如何通过会商审校机制形成可追溯治理闭环。

## 核心结论

业务口径、数据版本和分析方法分别落实责任主体，并通过会商审校、发布授权和复盘留痕机制共同保护预测结论的一致性与可追溯性。

## 主论证链

`责任主体 → 明确责任对象 → 协同/控制机制 → 一致、可追溯的预测结论`

## Argument Topology

`governance chain`

页面展示责任主体、各自控制对象以及共同治理机制。角色之间可协同，但不得互相替代责任；最终结果必须说明具体被保护的对象。

## Relation Contract

- Node Role：并行责任主体、各自责任对象、共同控制机制、受保护结果。
- Edge Semantics：主体对责任对象承担明确责任；共同控制机制对关键判断和变更实施控制；控制最终落到可验证结果。
- Direction / Cardinality：`Actor → Responsibility Object → Control Mechanism → Protected Outcome`；多个 Actor / Responsibility Object 可汇入共同控制层。
- Invariant：Control Mechanism 不能与 Actor 变成同层第四主体；每个主体必须先绑定自己的责任对象，再进入共同治理层。
- Confusable With：Parallel。
- Disambiguation Rule：Governance 回答“谁对什么负责、通过什么控制保护什么结果”；Parallel 只回答“结论由哪些同层维度构成”。

## Relation Units

1. 业务牵头方负责指标口径、判断尺度和结论边界；
2. 数据责任方负责数据来源、质量校验和版本可追溯；
3. 分析执行方负责模型方法、情景假设和计算过程可解释；
4. 会商审校与发布机制控制结论一致性、变更授权和复盘留痕。

## 完整文字稿

统一预测要持续运行，需要把业务口径、数据版本和分析方法分别绑定到明确责任主体。业务牵头方负责指标定义、判断尺度和结论适用边界，确保不同周期围绕同一业务问题形成判断；数据责任方负责来源登记、质量校验和版本管理，确保输入能够追溯；分析执行方负责模型方法、情景假设和计算过程，保证结果可解释、可复核。

三类责任通过会商审校、发布授权和复盘留痕机制衔接。会商审校控制关键结论是否符合共同口径，发布授权控制正式成果版本和变更责任，复盘留痕记录偏差原因及后续规则参数调整。治理结果落到预测结论口径一致、来源可追溯、过程可复核和变更有记录。

## 上屏文字

- 明确业务、数据和分析责任，并以审校、授权和留痕机制保护预测结论的一致性与可追溯性
  - 业务牵头方负责指标口径、判断尺度和结论边界
    - 控制对象：业务定义、周期间判断尺度、正式结论适用范围
  - 数据责任方负责数据来源、质量校验和版本可追溯
    - 控制对象：数据来源登记、质量状态、版本变更与使用记录
  - 分析执行方负责模型方法、情景假设和计算过程可解释
    - 控制对象：模型版本、参数假设、情景设置与计算过程
  - 会商审校与发布机制控制结论一致性、变更授权和复盘留痕
    - 受保护结果：结论口径一致、来源可追溯、过程可复核、变更有记录

## 视觉结构

页面将三个责任主体分别与自己的责任对象绑定，再汇入共同治理机制；治理机制进一步连接到明确受保护结果。可使用“主体—责任—机制—结果”的治理链或三主体汇入共同控制层的结构。不得把主体名称独立放成无责任卡片，也不得用抽象“保障”作为终点而不说明保障什么。

## 演讲者备注

统一预测进入常态运行后，最容易出现的问题来自责任边界不清：业务口径由谁确认，数据版本由谁负责，模型假设发生变化后由谁解释。如果这些责任没有绑定到具体对象，跨周期结论就很难稳定复核。

因此，业务、数据和分析三方分别承担明确责任，再通过会商审校、发布授权和复盘留痕衔接。治理的最终效果可以直接检查：结论口径是否一致、数据来源能否追溯、分析过程能否复核、变更是否有记录。

## 作者自检

1. 每个主体都与明确责任对象绑定，不能只列组织名称。
2. 三类责任边界互不替代，协同机制不吞并主体责任。
3. 会商审校、发布授权、复盘留痕分别说明控制什么。
4. 最终结果具体到一致性、可追溯、可复核和变更记录，不使用空泛“保障”。
5. Evidence 只解释直接父级的责任或控制对象。
6. 上屏纯文本可恢复 `主体 → 责任/控制对象 → 治理机制 → 受保护结果`。

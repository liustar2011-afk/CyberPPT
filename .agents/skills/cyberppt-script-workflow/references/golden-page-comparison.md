# 黄金页面 06：Comparison

> 教学定位：展示 `comparison`。比较对象必须使用同一评价维度，差异结论由同维度证据建立，避免把无关特征拼成“优劣对比”。

## 页面使命

说明分散预测方式与统一预测体系在关键运行能力上的差异。

## 核心结论

统一预测体系通过统一数据版本、分析维度、跨周期校核和复盘机制，使预测工作从分散产出提升为可比较、可追溯、可持续更新的运行能力。

## 主论证链

`同一评价标准 → 分散方式现状 vs 统一体系目标状态 → 能力差异结论`

## Argument Topology

`comparison`

所有比较行都使用同一对对象：分散预测方式与统一预测体系。每一行只改变评价维度，不改变比较对象或判断标准。

## Relation Contract

- Node Role：固定比较对象 A / B + 多个共同评价维度。
- Edge Semantics：A 与 B 在同一评价维度上形成状态差异，不表示 A 流转、演进或转化为 B。
- Direction / Cardinality：无流程方向；两个固定对象 × N 个评价维度。
- Invariant：每一行都必须使用同一对比较对象和同一评价标准，左右 Evidence 必须成对。
- Confusable With：Mapping / Roadmap。
- Disambiguation Rule：Comparison 回答“A 与 B 在维度 D 上有什么差异”；Mapping 回答“A 对应什么 B”；Roadmap 回答“状态如何逐步跃迁”。

## Relation Units

1. 数据基础：分散版本管理 ↔ 统一目录、口径和版本；
2. 分析范围：单点总量判断 ↔ 多维、多情景研判；
3. 周期衔接：月季年独立生产 ↔ 跨周期统一校核；
4. 运行反馈：发布后结束 ↔ 误差复盘持续回写。

## 完整文字稿

分散预测方式与统一预测体系的差异可以从四个共同维度判断。数据基础方面，分散方式容易形成不同报表、周期和团队各自维护版本的情况，统一体系要求目录、指标口径和数据版本一致。分析范围方面，单点总量判断难以表达结构、区域、时段和不确定性，统一体系将区间、概率和情景纳入共同分析框架。

周期衔接方面，月度、季度和年度独立生产时，同一风险难以相互验证；统一体系通过共同框架实现滚动、校核和展望之间的连续衔接。运行反馈方面，预测结果发布后若缺少复盘，偏差难以进入下一轮规则和参数调整；统一体系通过误差复盘形成持续回写。四项差异共同决定预测工作能否沉淀为可比较、可追溯、可持续更新的能力。

## 上屏文字

- 统一预测体系在四个共同维度上形成可比较、可追溯、可持续更新的运行能力
  - 数据基础：分散版本管理 → 统一目录、口径和版本
    - 同一指标和同一周期使用可追溯的数据版本，减少跨团队、跨报告口径差异
  - 分析范围：单点总量判断 → 多维、多情景研判
    - 结构、区域、时段、区间、概率和情景共同解释风险来源与不确定性
  - 周期衔接：月季年独立生产 → 跨周期统一校核
    - 月度滚动、季度校核和年度展望在共同框架内相互验证
  - 运行反馈：发布后结束 → 误差复盘持续回写
    - 偏差进入数据版本、分析规则和预测参数调整，推动下一轮判断更新

## 视觉结构

页面使用同一组四行评价维度比较两个对象。左、右两列固定为“分散预测方式”和“统一预测体系”，中间或行首固定显示评价维度。每行证据与同一维度绑定。视觉强调差异方向，但不得把四行误画成先后步骤，也不得在某一行更换比较对象。

## 演讲者备注

这页关注的是预测能力能否形成稳定运行机制。若数据版本、分析范围、业务周期和反馈机制各自分散，即使每次报告能够按时产出，也难以保证不同周期结论可比较、偏差可追溯。

统一体系的价值体现在同一套评价维度上：数据有共同版本，分析能表达多种风险形态，月季年能够互相校核，发布后的偏差还能进入下一轮调整。四个维度共同说明能力从一次性产出走向持续运行。

## 作者自检

1. 所有比较行都使用同一对比较对象，没有中途切换主体。
2. 四个 Relation Units 都是可命名的统一评价维度。
3. 每行左右两端具有可比性，证据解释同一维度的状态差异。
4. 核心结论由四项差异共同建立，没有额外引入未比较的新判断。
5. 视觉上能横向读取每一行，也能纵向理解四个评价维度。
6. 页面不得把“现状 → 目标”箭头误解为四阶段实施路线。

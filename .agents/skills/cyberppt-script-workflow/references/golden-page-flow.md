# 黄金页面 02：Flow / Feedback Loop

> 教学定位：展示 `directed chain + feedback`。本文中的 Relation Units 是示例标签，映射到 AUTHOR Contract 的阶段性 independent arguments，不新增运行时字段。

## 页面使命

说明统一数据、预测研判、审校发布和误差复盘如何通过真实业务交接形成持续更新的预测运行闭环。

## 核心结论

统一数据、预测研判、审校发布和误差复盘通过明确交接物连续衔接，并将复盘结果回写数据、规则和参数，形成持续更新的风险预警闭环。

## 主论证链

`数据与规则 → 预测研判 → 审校发布 → 误差复盘 → 数据/规则/参数回写`

## Argument Topology

`directed chain + feedback`

四个 Relation Units 按真实业务交接顺序连接。每条正向边都必须存在可命名的交接物；复盘结果必须回写到明确的数据版本、分析规则或预测参数。月度、季度和年度属于共用框架中的不同业务周期，不作为串行阶段处理。

## Relation Contract

- Node Role：业务阶段、阶段交接物、反馈目标。
- Edge Semantics：前一阶段通过真实业务交接物进入后一阶段；反馈边将复盘结论回写到明确对象。
- Direction / Cardinality：主链 1 → 1 顺序推进，并存在末端 → 前端的反馈边。
- Invariant：每条正向边必须存在可命名的业务交接；反馈必须明确回写数据版本、分析规则或模型参数，不能只画装饰性回环。
- Confusable With：Causal / Roadmap。
- Disambiguation Rule：Flow 的箭头表示真实业务交接；Causal 表示前因产生后果；Roadmap 表示满足条件后的状态跃迁。

## Relation Units

1. 数据与规则准备｜形成可直接进入预测研判的统一输入；
2. 预测研判｜形成可提交会商审校的研判结论；
3. 审校发布｜形成可追溯的正式发布版本；
4. 误差复盘｜形成可回写下一轮预测的数据、规则和参数调整项。

## 业务交接物

1. 数据与规则 → 预测研判｜统一数据目录、指标口径、版本标识和周期范围；
2. 预测研判 → 审校发布｜基准预测、情景分析、专家修正后的研判结论及关键假设；
3. 审校发布 → 误差复盘｜正式发布版本、结论清单、实际结果与误差记录；
4. 误差复盘 → 数据/规则/参数｜偏差原因、口径调整、版本修订和模型参数修正。

## 完整文字稿

统一预测闭环从可追溯的数据和规则输入开始。统计、高频负荷、气象、交易和新型主体等数据按业务需要接入，并统一数据目录、指标口径、版本标识和周期范围；这些共同输入进入预测研判，形成基准预测、情景分析和专家修正后的研判结论及关键假设。

研判结论提交会商审校，经过口径核对、结论确认和发布管理后形成月报、季报、年报或专题专报等正式版本。正式成果发布后，实际结果与预测结论进入误差复盘，形成偏差原因、口径调整、版本修订和模型参数修正，并回写下一轮数据与规则准备和预测研判。

## 上屏文字

- 四个业务阶段通过明确交接物连续衔接，并以复盘回写形成持续风险预警闭环
  - 数据与规则准备｜形成统一输入
    - 交接物：统一数据目录、指标口径、版本标识、周期范围
  - 预测研判｜形成可审校的研判结论
    - 交接物：基准预测、情景分析、专家修正结果及关键假设
  - 审校发布｜形成可追溯的正式成果
    - 交接物：正式发布版本、结论清单及发布记录
  - 误差复盘｜形成下一轮调整项
    - 回写物：偏差原因、口径调整、版本修订、模型参数修正

## 视觉结构

总论位于页面顶部首个阅读入口，不放入流程节点。主体采用连续主链并保留一条明确反馈边，关系固定为：

`数据与规则 → 预测研判：顺序衔接｜交接物：统一数据目录、指标口径、版本标识、周期范围`

`预测研判 → 审校发布：顺序衔接｜交接物：研判结论、情景结果、关键假设`

`审校发布 → 误差复盘：顺序衔接｜交接物：正式发布版本、结论清单、误差记录`

`误差复盘 → 数据与规则：反馈回流｜回写物：偏差原因、口径调整、版本修订、参数修正`

每个阶段节点只承载本阶段动作和输出，交接物贴近对应边呈现。月度、季度和年度作为共用框架中的业务周期表达，保持与流程阶段分离。

## 演讲者备注

Flow 页的判断重点在于阶段之间实际交接什么。数据与规则阶段向预测研判交付统一输入，预测研判向审校发布交付研判结论和关键假设，审校发布向误差复盘交付正式版本及实际误差记录。

复盘完成后，偏差原因、口径调整、版本修订和模型参数修正回到下一轮预测输入。只要这些交接物和回写物能够被明确命名，流程关系就可以独立于页面排版成立，也能与单纯因果链清楚区分。

## 作者自检

1. 四个 Relation Units 均为真实业务阶段，每个阶段都有明确输出。
2. 三条正向边均存在可命名的交接物，能够回答“前一阶段具体交给后一阶段什么”。
3. 反馈边明确说明回写对象和回写内容，不使用装饰性回环。
4. 月度、季度和年度保持为共用业务周期，不与四个流程阶段混排。
5. 上屏纯文本可恢复阶段、交接物、反馈方向和回写内容。
6. 视觉结构中的关系标签保留“顺序衔接 / 反馈回流”，Stage2 无需依靠箭头形状猜测语义。

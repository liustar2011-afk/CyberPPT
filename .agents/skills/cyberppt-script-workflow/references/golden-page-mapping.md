# 黄金页面 05：Mapping

> 教学定位：展示 `mapping`。每个问题端点必须与一个明确响应端点相连，对应规则可解释，映射不得误画成流程。

## 页面使命

说明关键供需风险问题如何对应到具体研判能力。

## 核心结论

供给波动、需求峰值、市场互济和新能源偏差分别对应可用能力、负荷情景、互济空间和概率情景分析，形成从风险问题到研判能力的可解释映射。

## 主论证链

`风险问题 A/B/C/D → 对应研判能力 A/B/C/D；4 组 1:1 映射共同覆盖关键供需风险`

## Argument Topology

`mapping`

页面同时显示问题端与响应端。每一对映射都必须说明“该能力具体回答什么问题”，不同映射对之间没有默认先后顺序。

## Relation Contract

- Node Role：问题端点、响应端点、对应规则。
- Edge Semantics：问题端单向指向能够回答该问题的能力端，表示“问题由哪项能力响应”，不表示流程先后、状态演进或双向作用。
- Direction / Cardinality：本示例固定为 `Problem → Response`，四组均为 1:1；实际业务出现 1:N 或 N:1 时必须按真实关系保留 Cardinality。
- Invariant：问题端与响应端必须同时可见；每条边必须保留真实方向和基数，不能为了视觉整齐强制一一对应，也不能把多组映射串成流程。
- Confusable With：Comparison。
- Disambiguation Rule：Mapping 回答“A 对应什么 B”；Comparison 回答“A 与 B 在同一评价维度 D 上有什么差异”。

## Relation Units

1. 1:1｜供给波动 → 可用能力与检修受限分析；
2. 1:1｜需求峰值 → 负荷情景与峰谷爬坡分析；
3. 1:1｜市场互济 → 跨区跨省交易与可调用空间分析；
4. 1:1｜新能源偏差 → 概率区间与多情景分析。

## 完整文字稿

供需风险问题需要与对应的研判能力逐项连接。供给波动关注名义装机中有多少能够实际调用，需要结合检修、故障和受限情况分析可用能力；需求峰值关注峰值水平、持续时长和爬坡压力，需要通过负荷情景分析判断风险时点。

市场互济关注本地缺口能否通过外部资源缓释，需要分析跨区跨省交易和可调用互济空间；新能源偏差关注风光出力的不确定性，需要用概率区间和多情景分析表达不同偏差条件下的风险变化。四组映射均从风险问题指向对应研判能力，共同覆盖供需研判中的关键问题。

## 上屏文字

- 四类关键供需风险分别对应明确研判能力，形成可解释的问题—响应映射
  - 问题｜供给波动 → 响应｜可用能力与检修受限分析
    - 回答｜名义装机中有多少能够实际调用，以及供给边界如何变化
  - 问题｜需求峰值 → 响应｜负荷情景与峰谷爬坡分析
    - 回答｜峰值何时出现、持续多久、快速爬坡会形成多大平衡压力
  - 问题｜市场互济 → 响应｜跨区跨省交易与可调用空间分析
    - 回答｜本地缺口有多少能够通过外部互济资源缓释
  - 问题｜新能源偏差 → 响应｜概率区间与多情景分析
    - 回答｜不同风光出力偏差下，缺口概率和风险区间如何变化

## 视觉结构

页面使用清晰的左右映射：左侧固定为四类风险问题，右侧固定为四类对应研判能力；每组连接从问题端单向指向能力端。本示例四组关系均为 1:1，不通过视觉对称暗示双向作用。核心结论位于映射区域上方，不得用连续箭头把四行串成业务流程，也不得只展示能力端而隐藏问题端。

关系边保持独立解析：

供给波动 → 可用能力与检修受限分析：问题回应
需求峰值 → 负荷情景与峰谷爬坡分析：问题回应
市场互济 → 跨区跨省交易与可调用空间分析：问题回应
新能源偏差 → 概率区间与多情景分析：问题回应

## 演讲者备注

讲解时重点解释映射边的含义，而不逐行复述四组内容。这里的方向只表示“这个问题由哪项能力响应”，不表示问题在时间上流转到能力，也不表示问题造成能力。若交换左右端点后语义发生变化，说明映射具有真实方向，应保留 `Problem → Response`。

本例四组都是 1:1，但 1:1 只来自业务事实，不能作为版式规则。若一个问题需要多项能力共同响应，应保留 1:N；若多类问题由同一能力处理，应保留 N:1。视觉整齐不能优先于真实 Cardinality。

## 作者自检

1. 上屏统一采用“问题｜A → 响应｜B / 回答｜业务问题”的微语法。
2. 左右两端对象同时可见，不能只写能力清单。
3. 四组映射均能解释“为什么这一能力对应这一问题”。
4. 每一对 Relation Unit 独立成立，不依赖上一行或下一行补足语义。
5. Evidence 解释映射作用，没有只重复两端名称。
6. 四条边均为 `Problem → Response` 的 1:1 对应，不使用 `↔` 暗示双向关系。
7. 视觉关系保持逐项对应，不被误画成从上到下的流程。
8. 上屏纯文本可恢复全部映射端点、方向、Cardinality 和对应规则。

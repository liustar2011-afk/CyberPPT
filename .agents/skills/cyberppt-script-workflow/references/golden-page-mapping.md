# 黄金页面 05：Mapping

> 教学定位：展示 `mapping`。每个问题端点必须与一个明确响应端点相连，对应规则可解释，映射不得误画成流程。

## 页面使命

说明关键供需风险问题如何对应到具体研判能力。

## 核心结论

供给波动、需求峰值、市场互济和新能源偏差分别对应可用能力、负荷情景、互济空间和概率情景分析，形成从风险问题到研判能力的可解释映射。

## 主论证链

`风险问题 A/B/C/D ↔ 对应研判能力 A/B/C/D → 覆盖关键供需风险`

## Argument Topology

`mapping`

页面同时显示问题端与响应端。每一对映射都必须说明“该能力具体回答什么问题”，不同映射对之间没有默认先后顺序。

## Relation Contract

- Node Role：问题端点、响应端点、对应规则。
- Edge Semantics：问题与能够回答该问题的能力建立明确对应，不表示流程先后或双向作用。
- Direction / Cardinality：本示例为 1:1；实际业务可为 1:N 或 N:1，按真实关系保留 Cardinality。
- Invariant：问题端与响应端必须同时可见，不能为了视觉整齐强制一一对应，也不能把映射行串成流程。
- Confusable With：Comparison。
- Disambiguation Rule：Mapping 回答“A 对应什么 B”；Comparison 回答“A 与 B 在同一评价维度 D 上有什么差异”。

## Relation Units

1. 供给波动 → 可用能力与检修受限分析；
2. 需求峰值 → 负荷情景与峰谷爬坡分析；
3. 市场互济 → 跨区跨省交易与可调用空间分析；
4. 新能源偏差 → 概率区间与多情景分析。

## 完整文字稿

供需风险问题需要与对应的研判能力逐项连接。供给波动关注名义装机中有多少能够实际调用，需要结合检修、故障和受限情况分析可用能力；需求峰值关注峰值水平、持续时长和爬坡压力，需要通过负荷情景分析判断风险时点。

市场互济关注本地缺口能否通过外部资源缓释，需要分析跨区跨省交易和可调用互济空间；新能源偏差关注风光出力的不确定性，需要用概率区间和多情景分析表达不同偏差条件下的风险变化。四组映射共同覆盖供需研判中的关键问题。

## 上屏文字

- 四类关键供需风险分别对应明确研判能力，形成可解释的问题—响应映射
  - 供给波动 → 可用能力与检修受限分析
    - 回答“名义装机中有多少能够实际调用，以及供给边界如何变化”
  - 需求峰值 → 负荷情景与峰谷爬坡分析
    - 回答“峰值何时出现、持续多久、快速爬坡会形成多大平衡压力”
  - 市场互济 → 跨区跨省交易与可调用空间分析
    - 回答“本地缺口有多少能够通过外部互济资源缓释”
  - 新能源偏差 → 概率区间与多情景分析
    - 回答“不同风光出力偏差下，缺口概率和风险区间如何变化”

## 视觉结构

页面使用清晰的左右映射：左侧为四类风险问题，右侧为四类对应研判能力，中间使用一一对应的连接关系。每一行形成完整的问题—响应对。核心结论位于映射区域上方。不得用连续箭头把四行串成业务流程，也不得只展示右侧能力而隐藏问题端。

## 演讲者备注

研判能力的价值需要回到具体业务问题。供给侧要回答实际可调用能力，需求侧要回答峰值和爬坡压力，市场侧要回答外部互济能够缓释多少本地缺口，新能源侧要回答出力偏差会让风险区间如何变化。

把问题与能力逐项对应后，可以直接判断现有分析是否覆盖了关键风险，也能避免把多项技术能力堆叠在页面上却看不出各自解决什么问题。

## 作者自检

1. 左右两端对象同时可见，不能只写能力清单。
2. 四组映射均能解释“为什么这一能力对应这一问题”。
3. 每一对 Relation Unit 独立成立，不依赖上一行或下一行补足语义。
4. Evidence 解释映射作用，没有只重复两端名称。
5. 视觉关系保持一一对应，不被误画成从上到下的流程。
6. 上屏纯文本可恢复全部映射端点和对应规则。

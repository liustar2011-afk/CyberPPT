# 黄金页面 03：Causal Chain

> 教学定位：展示 `directed chain` 的因果表达。Relation Units 是教学标签，映射到 AUTHOR Contract 的独立论证/推理单元，不新增运行时字段。

## 页面使命

说明业务对象和不确定性变化为什么会形成统一分析能力升级需求。

## 核心结论

研判对象与不确定性同步增加，使单一总量预测难以支撑跨周期风险判断，统一分析能力需要向多维、多情景和多周期协同升级。

## 主论证链

`业务对象扩展 → 分析要求增加 → 现有能力缺口显现 → 统一分析能力升级`

## Argument Topology

`directed chain`

每个 Relation Unit 都是前一状态产生的业务后果，并为下一判断提供必要前提。不得把四项改写成互不相关的并列建设任务。

## Relation Contract

- Node Role：起因、直接后果、中间后果、最终能力结论。
- Edge Semantics：前一节点真实产生后一节点，关系必须能够用“因为 A，所以 B”解释。
- Direction / Cardinality：单向 1 → 1 连续因果链。
- Invariant：每条边都必须独立通过“因为 A，所以 B”测试；排版、箭头或叙事顺序不能替代因果证据。
- Confusable With：Flow。
- Disambiguation Rule：Causal 的箭头回答“为什么 B 会发生”；Flow 的箭头回答“业务从 A 交接什么到 B”。

## Relation Units

1. 供给、需求、市场和新型主体共同进入研判范围；
2. 研判从总量趋势扩展到结构、区域、时段、概率和情景；
3. 分散的数据版本与周期规则难以支撑跨周期验证；
4. 统一分析能力需要贯通数据、模型、审校和复盘。

## 完整文字稿

供需研判对象持续扩展，供给侧可用能力、需求侧负荷形态、市场互济以及新型主体运行特征均会改变平衡判断。对象增加后，分析要求随之从单一总量趋势扩展到结构、区域、时段、概率和情景。

分析维度增加后，月度、季度和年度若继续使用分散的数据版本、指标口径和判断尺度，同一风险难以跨周期验证，预测偏差也难以回溯到具体数据和模型假设。由此形成的能力缺口要求进一步贯通数据、模型、审校和复盘机制，使多维、多情景研判能够在不同周期内连续运行。

## 上屏文字

- 研判对象与不确定性同步增加，推动统一分析能力向多维、多情景和多周期协同升级
  - 供给、需求、市场和新型主体共同进入研判范围
    - 可用能力、负荷形态、市场互济和新型主体运行特征都会改变供需平衡判断
  - 研判要求由总量趋势扩展到结构、区域、时段、概率和情景
    - 风险判断需要同时解释“哪里发生、何时发生、发生概率和不同情景下如何变化”
  - 分散的数据版本与周期规则难以支撑跨周期验证
    - 月度、季度和年度结论缺少一致口径时，同一风险难以相互校核，偏差也难以追溯
  - 统一分析能力需要贯通数据、模型、审校和复盘
    - 统一输入、研判、会商与反馈机制使多维结论能够跨周期持续更新

## 视觉结构

页面采用单一有向主链。四个 Relation Units 按“变化—要求—缺口—建设结论”依次连接，箭头表达真实因果或依赖关系。Evidence 紧贴所属节点，不在节点间另设无来源的新阶段。核心结论位于链路上方或终点附近的总论区域，但不重复作为第五个流程节点。

## 演讲者备注

能力升级的起点来自业务对象变化。供给、需求、市场和新型主体同时进入研判范围后，原有只看总量趋势的方法难以解释结构、区域、时段以及不确定性差异。

随着分析维度增加，不同周期若继续使用分散的数据版本和判断规则，月度发现的风险很难在季度和年度中得到一致验证。由此需要把数据、模型、审校和复盘贯通起来，使同一风险在不同尺度上可比较、可解释、可回溯。

## 作者自检

1. 四个 Relation Units 能形成连续的“变化 → 新要求 → 当前缺口 → 建设结论”。
2. 每条箭头都能用一句业务语言解释，不能仅凭排版制造因果。
3. “统一分析能力升级”出现在链路后端，没有提前作为前置证据。
4. Evidence 只证明直接父级，没有把并列事实误写成时间顺序。
5. 去掉任一中间 Relation Unit 后，因果链应出现可解释的逻辑缺口。
6. 上屏纯文本可恢复方向关系，不能退化为四个平行卡片。

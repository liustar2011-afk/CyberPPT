# 黄金页面 03：Causal Chain

> 教学定位：展示 `directed chain` 的因果表达。Relation Units 是教学标签，映射到 AUTHOR Contract 的独立论证/推理单元，不新增运行时字段。

## 页面使命

说明分散的数据口径和版本为什么会逐级削弱跨周期风险预警。

## 核心结论

数据口径和版本分散会先造成同一指标计算基准不一致，继而使月季年结论难以校核、预测偏差难以追溯，最终削弱风险预警的持续更新能力。

## 主论证链

`数据口径和版本分散 → 同一指标计算基准不一致 → 跨周期结论难以校核 → 偏差难以追溯 → 风险预警难以持续更新`

## Argument Topology

`directed chain`

每个 Relation Unit 都是前一状态产生的直接业务后果，并为下一判断提供必要前提。每条边均需能够单独回答“为什么后一状态会发生”，不得用页面顺序或箭头代替因果依据。

## Relation Contract

- Node Role：起因、直接后果、中间后果、最终业务影响。
- Edge Semantics：前一节点真实产生后一节点，关系必须能够用“因为 A，所以 B”解释。
- Direction / Cardinality：单向 1 → 1 连续因果链。
- Invariant：每条边都必须独立通过“因为 A，所以 B”测试；排版、箭头或叙事顺序不能替代因果证据。
- Confusable With：Flow。
- Disambiguation Rule：Causal 的箭头回答“为什么 B 会发生”；Flow 的箭头回答“业务从 A 交接什么到 B”。

## Relation Units

1. 数据口径和版本分散，使同一指标在不同周期形成不同计算基准；
2. 计算基准不一致，使月度、季度和年度结论难以在同一尺度上比较与校核；
3. 结论难以稳定校核，使预测偏差难以定位到具体数据、规则或模型假设；
4. 偏差难以追溯，使复盘结果难以稳定回写，风险预警无法持续更新。

## 完整文字稿

月度、季度和年度预测若分别维护指标口径、数据版本和计算规则，同一指标可能在不同周期使用不同基准。基准一旦不一致，月度发现的风险就难以与季度、年度结论直接比较，同一风险也难以判断是业务变化还是口径变化造成。

跨周期结论缺少稳定校核基础后，预测偏差就难以进一步定位到具体数据版本、分析规则或模型假设。偏差原因无法追溯，复盘结论也难以准确回写到下一轮数据、规则和参数调整中，最终使风险预警难以形成持续更新的运行闭环。

## 上屏文字

- 数据口径和版本分散会逐级削弱跨周期风险预警的持续更新能力
  - 起因｜数据口径和版本分散
    - 直接后果｜同一指标在不同周期形成不同计算基准
  - 后果1｜同一指标计算基准不一致
    - 直接后果｜月度、季度和年度结论难以在同一尺度上比较与校核
  - 后果2｜跨周期结论难以稳定校核
    - 直接后果｜预测偏差难以定位到具体数据版本、分析规则或模型假设
  - 后果3｜预测偏差难以追溯
    - 直接后果｜复盘结果难以稳定进入下一轮数据、规则和参数调整
  - 业务影响｜风险预警难以持续更新

## 视觉结构

- 视觉对象：起因“数据口径和版本分散”、三个连续中间后果，以及最终业务影响“风险预警难以持续更新”。
- 关系语义：节点之间全部为真实因果，每一条边表达“前因导致后果”，不承担业务交接或时间推进语义。
- 方向 / Cardinality：单向连续 1→1 因果链；方向不可反转，任一中间节点删除后应出现可解释的因果缺口。
- 分组 / 层级：核心结论位于上位总论层；起因、中间后果、最终影响处于一条主因果链；Evidence 紧贴所属节点，只证明直接父级与下一后果之间的因果机制。
- 禁止误读：不得把链条画成“先做什么、后做什么”的业务流程或 Roadmap；不得把节点拆成平行卡片后只靠页面位置暗示因果。

原子关系边：

`数据口径和版本分散 → 同一指标计算基准不一致：因果导致`

`同一指标计算基准不一致 → 跨周期结论难以校核：因果导致`

`跨周期结论难以校核 → 预测偏差难以追溯：因果导致`

`预测偏差难以追溯 → 风险预警难以持续更新：因果导致`

## 演讲者备注

讲解时不再逐节点复述链条，重点说明因果关系如何被验证。每条边至少通过两个测试：一是能够完整说成“因为 A，所以 B”；二是进行反事实检查——若 A 不存在，B 是否仍会通过同一机制发生。只有两项都成立，才保留为因果边。

若某条关系只能解释“先发生 A、后发生 B”，应改为 Flow 或 Roadmap；若只能说明 A 与 B 同时存在或共同支撑结论，应改为 Parallel / Convergence。这样可以防止页面排版把叙事顺序伪装成因果。

## 作者自检

1. 上屏采用“因果角色｜状态 / 直接后果｜下一状态”的稳定微语法。
2. 五项视觉结构合同完整，可恢复节点角色、因果方向、层级和禁止误读项。
3. 每个 Relation Unit 都明确陈述“前一状态造成的直接后果”。
4. 四条因果边均可独立通过“因为 A，所以 B”和反事实测试。
5. 任意删除一个中间节点，前后两端的因果解释都会出现明显缺口。
6. 页面不混入实施步骤、业务交接或时间阶段，避免与 Flow / Roadmap 混淆。
7. Evidence 只证明直接父级与下一后果之间的因果关系。
8. 上屏纯文本和视觉结构均可恢复同一条因果链，Stage2 无需根据排版猜测关系。

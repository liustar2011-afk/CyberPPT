# 黄金页面 01：Parallel / MECE Classification

> 教学定位：展示 `parallel grouping`。本文中的 Relation Units 是示例标签，映射到 AUTHOR Contract 的 independent arguments，不新增运行时字段。

## 页面使命

说明统一预测体系需要从哪些同层建设维度共同形成持续风险预警能力。

## 核心结论

统一预测体系从研判范围、周期规则和运行机制三个同层维度协同建设，形成可持续更新的风险预警能力。

## 主论证链

`统一预测体系 → 研判范围 + 周期规则 + 运行机制 → 持续风险预警`

## Argument Topology

`parallel grouping`

三个一级业务语义单元都回答同一上位问句：“统一预测体系需要建设哪一个能力维度？”三者处于相同业务尺度，彼此独立并共同支撑总论；不得画成实施先后或因果链。

## Relation Contract

- Node Role：一个 Core Message + 多个同维度兄弟 Relation Units。
- Edge Semantics：兄弟单元分别支撑同一 Core Message，兄弟之间不建立默认关系。
- Direction / Cardinality：N → 1；兄弟单元之间无方向。
- Invariant：所有兄弟 Relation Units 必须处于同一分解维度，并能回答完全相同的上位问句。
- Confusable With：Convergence。
- Disambiguation Rule：Parallel 回答“结论由哪些同层维度构成”；Convergence 回答“哪些独立输入共同生成一个结果”。

## Relation Units

1. 研判范围｜扩展分析对象与成果形态；
2. 周期规则｜统一月季年数据口径、版本和判断尺度；
3. 运行机制｜贯通预测、审校、发布和复盘闭环。

## 完整文字稿

统一预测体系需要从三个同层建设维度同时完善。研判范围解决“分析什么、形成什么成果”，将供给、需求、市场和新型主体等影响因素纳入共同研判，并把成果由单点预测扩展到结构、区域、时段、区间、概率、情景以及清单、图谱、专报和会商支撑。

周期规则解决“按什么共同尺度判断”，使月度、季度和年度分析使用一致的数据版本、指标口径和判断尺度，并固化共同的预测分析与报告生产规则。运行机制解决“结论如何持续更新”，将基准预测、情景分析、专家修正、会商审校、成果发布和误差复盘连接成持续闭环。

三个维度分别处理研判边界、判断规则和运行机制，业务尺度一致、责任边界清晰，共同支撑持续风险预警。

- 统一预测体系从三个同层建设维度形成可持续更新的风险预警能力
  - 研判范围｜扩展分析对象与成果形态

## 视觉结构

总论位于页面上方入口区域，先于所有分组进入视线。主体固定为三个同级语义分区：研判范围、周期规则、运行机制。三组使用一致的标题句法、信息深度和视觉权重，每组标题置于所属 Evidence 之上。三组均直接支撑统一预测体系，不在兄弟单元之间建立箭头、先后关系或因果关系。

## 演讲者备注

讲解时先锁定“同层”这一判别条件：三项内容都回答“统一预测体系需要建设哪一个能力维度”，因此应横向解释各自边界，不能沿页面位置讲成先做研判范围、再做周期规则、最后做运行机制。

口头补充只解释三项为何互不重叠：研判范围界定分析与成果边界，周期规则统一跨周期判断尺度，运行机制保证结论持续运行。若讨论实施先后、里程碑或进入条件，应切换到 Roadmap 语法，而不在本页附加时间顺序。

## 作者自检

1. 三个 Relation Units 均采用“维度名｜该维度承担的建设动作”句法。
2. 三个 Relation Units 都能独立回答“统一预测体系需要建设哪一个能力维度？”。
3. 三组业务尺度一致：研判范围处理分析边界；周期规则处理判断尺度；运行机制处理持续运行。
4. 遮住 Evidence 后，三个 Relation Units 仍可独立说明对总论的贡献。
5. Evidence 只证明直接父级，没有把补充事实升级为第四个主维度。
6. 上屏可从纯文本恢复 `Core Message → Relation Units → Evidence`，且不会误读为顺序关系。

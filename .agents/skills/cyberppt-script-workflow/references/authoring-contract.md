# CyberPPT Analytical AUTHOR Contract

This file is the single operational authority for `AUTHOR`, `CRITIQUE`, `REWRITE`,
targeted page revision and whole-deck script review when the approved Deck Plan selects
`authoring_mode: analytical`. Read it completely before taking any of those actions.
Repository-level `AGENTS.md` remains a hard constraint; the local workflow
`AGENTS.md` defines the current Final Script version and source gate.

Do not blend this contract into faithful authoring. Project examples, customer names,
industry-specific facts and source-specific vocabulary belong in the current Foundation,
Deck Plan and Final Script, not in this reusable contract.

## 1. Product responsibility

Analytical authoring reorganizes source-grounded evidence into a clearer decision and
argument structure while preserving source boundaries, protected facts and claim
strength. It may synthesize supported judgments and relationships only when the
approved analytical mode and evidence justify them.

For new authoring, the target is Final Script 1.2:

- Stage 01 authors analytical `full_copy` and optional semantic structure such as
  `core_message`, `argument`, `relationships`, `visual_thesis` and `speaker_notes`;
- Stage 01 extracts narrow `fidelity_text` literals;
- Stage 01 does not author `onscreen`;
- Stage 02 derives runtime `onscreen_text` from the approved `full_copy` and may select,
  rewrite, merge, shorten, split and reorder ordinary content;
- only `fidelity_text` receives exact-copy semantics.

Analytical mode is not permission to introduce new facts, commitments, numbers,
responsibilities, achieved states or speculative relationships.

## 2. Required execution sequence

Run these steps in order for every analytical content page.

### Step 1 — Load the approved page brief

Read once per deck:

- document thesis and audience;
- approved authoring mode;
- source chapter structure.

For the target page read:

- page title, question and PLAN `logic` mission;
- page-bound `source_refs`;
- adjacent-page boundaries;
- relevant Foundation records;
- exact page source evidence;
- delivery mode and exposure boundary.

Do not rerun whole-document UNDERSTAND during local AUTHOR or Rewrite work.

### Step 2 — Pass the source gate

For current `script`-profile authoring, use the current `cyberppt.source_index.v2`,
generate fresh Page Source Packets, and pass Author Preflight before drafting or
materially rewriting. Missing, stale, invalid, partially resolved or blocked exact-source
state stops the action; do not fall back to Foundation previews or model memory.

The page packet and Author Preflight are derived runtime evidence, not new semantic
authorities.

### Step 3 — Lock source meaning and protected payload

Identify:

- actor / issuer / responsible party;
- action, status and business object;
- formal instrument identity and type;
- number, date, quantity and unit;
- responsibility;
- condition, trigger, exception and qualifier;
- scope and boundary;
- modality and claim strength;
- explicit relation and direction;
- source-supported room for synthesis.

A source statement cannot be strengthened because a nearby sentence uses a stronger
verb. A status belonging to one object cannot be applied to a group. A condition
attached to one action cannot be borrowed by another. A number cannot be reassigned to
another object merely because both appear on the same page.

### Step 4 — Define the analytical question and conclusion

Restate the approved page mission as one answerable audience question. Then write a
`core_message` only when a single supported conclusion genuinely governs the page.

`core_message` must:

- answer the approved question;
- name the business matter;
- preserve source status, responsibility and scope;
- distinguish source fact from author synthesis;
- use epistemic strength proportionate to evidence.

Do not fabricate a conclusion merely to fill a field. If the page is better represented
as several independent analytical judgments, retain them in `full_copy` and optional
argument structure without forcing one umbrella claim.

### Step 5 — Build claim–argument–evidence logic

Use `claim → independent argument(s) → source-grounded evidence` as the default reasoning
discipline.

For every argument:

- state the complete sub-judgment;
- bind it to page evidence;
- preserve protected payload;
- state whether the relation is direct, synthesis or supported relation;
- include material counter-condition or boundary when it changes the conclusion.

Do not manufacture causality, necessity, hierarchy, sequence or completeness from
lexical similarity or adjacency.

### Step 6 — Choose the smallest relationship grammar

Use a relationship grammar only when evidence supports it:

- `classification` — independent parts under one dimension;
- `mapping` — source, correspondence rule and target/use;
- `comparison` — matched objects under one criterion;
- `convergence` — independent inputs jointly support one result;
- `roadmap` — stage, trigger and newly reached state;
- `governance chain` — actor, mechanism, collaboration/resource and result;
- `flow/loop` — input, action, output, handoff and optional feedback.

Reasoning frameworks may organize the material:

- **Pyramid** — answer before independent reasons;
- **MECE** — only when a declared scope supports mutually exclusive and collectively
  exhaustive grouping;
- **SCR** — only when a real complication exists before the response.

Do not expose framework jargon to the audience unless it is itself useful content.

### Step 7 — Write analytical `full_copy`

`full_copy` is the complete Stage 01 semantic manuscript. It should be professional,
judgment-led analytical prose, not a dump of source rows and not a visually compressed
caption set.

Default patterns:

`paragraph judgment → supporting explanation → source-backed evidence / qualification`

For genuinely parallel branches:

`paragraph core conclusion → parallel sub-conclusion → supporting detail`

For a directional relation:

`initial state / condition → change or action → resulting state / implication`

For a bounded decision:

`recommended action → evidence basis → material condition / counterargument`

Keep every protected fact, condition and boundary needed to make the page's analytical
judgment defensible. Do not delete semantic material merely to reach a visual density
target; repair page scope or pagination when necessary.

### Step 8 — Critique analytical meaning

For each substantive proposition ask:

1. Is the actor supported?
2. Is the action or predicate supported?
3. Is the object the same business matter?
4. Is status preserved?
5. Is responsibility preserved?
6. Are numbers, dates and units exact?
7. Are conditions, triggers and qualifiers retained?
8. Is an asserted relation explicit or otherwise supportable under approved analytical
   synthesis?
9. Is modality / claim strength proportionate to evidence?
10. Has the prose turned a possibility, recommendation or plan into an achieved state?
11. Has a professional-domain completion been added without evidence?

Repair the earliest invalid reasoning link rather than polishing downstream wording.

## 3. Analytical synthesis discipline

### 3.1 Direct fact, synthesis and inferred relation

Use three explicit mental categories:

- **direct** — one source fact expressed without changing role or strength;
- **synthesis** — several source facts jointly support an author conclusion;
- **relation** — a relationship supported by explicit or typed relation evidence.

A synthesis must not imply that the source itself used the synthesized label. An inferred
relation must use appropriate epistemic strength. A recommendation remains visibly
non-achieved. A possible path cannot become a committed sequence.

### 3.2 Peer logic

Siblings must share one comparison dimension and comparable analytical depth.
Supplementary proof belongs beneath the claim it qualifies.

Do not put actors, methods, tasks and outcomes at the same level unless a declared
classification dimension genuinely makes them peers.

### 3.3 Subject and argument continuity

Trace each reasoning unit through:

- audience question;
- actor or subject;
- argument role.

Rules:

1. One reasoning unit owns one primary question.
2. Complete one actor's decision-bearing evidence before switching actors unless a
   supported relationship requires interleaving.
3. Follow source-supported responsibility order; never infer administrative rank from
   an institution name alone.
4. A transition names the handoff when the next unit changes from condition to response,
   diagnosis to action, input to output or evidence to implication.
5. Re-entry to an earlier actor needs a supported relationship such as feedback,
   comparison or responsibility handoff.

### 3.4 Page-logic normalization

Before finalizing `full_copy`:

1. restate one decision-bearing page question;
2. assign each candidate fact one principal role: context, basis, gap, response, result,
   condition or boundary;
3. build one readable relation among retained roles;
4. compare each paragraph with adjacent-page questions;
5. give each paragraph one principal role and one parent argument;
6. place results only after the action/condition that supports them or on the page that
   owns implementation/results;
7. run a role-switch Critic with titles and visual design hidden;
8. rewrite from the earliest invalid link.

Related facts without a directional or grouping predicate remain an inventory. Do not
invent a relationship solely to make the page look more analytical.

## 4. Final Script 1.2 field ownership

For an analytical content page, the required Stage 01 semantic base is:

- `title`;
- `full_copy`;
- `fidelity_text`;
- `source_refs`;
- `source_provenance`.

Analytical pages commonly also use, when supported:

- `mission`;
- `core_message`;
- `argument`;
- `visual_thesis`;
- `relationships`;
- `speaker_notes`.

For Final Script 1.2 content pages, do not create `onscreen`. Existing Final Script
1.0/1.1 artifacts remain backward compatible under the legacy contract.

### 4.1 `core_message`

Use one complete answer to the page question. Do not increase certainty, responsibility,
necessity or achievement beyond evidence.

### 4.2 `argument`

Use an explicit argument only when its topology is actually supported. A list of related
facts is not automatically an argument chain.

### 4.3 `relationships`

Every edge must have supported endpoints and a defensible predicate. Do not complete an
abstract edge by inventing a mechanism.

### 4.4 `visual_thesis`

Describe how the supported semantic structure should be made legible. It may identify a
classification, mapping, comparison, convergence, roadmap, governance chain or flow. It
is not permission to create a new business relationship.

### 4.5 `speaker_notes`

Notes may add source-grounded subordinate explanation, non-material context or a natural
transition. They must not contain a stronger claim than the page's Stage 01 semantic
content.

## 5. Extract narrow `fidelity_text`

After `full_copy` and analytical fields pass Critic, extract only literals that require
exact rendered spelling.

Valid candidates include:

- exact numbers with the minimum identifying context or unit;
- official policy, plan, standard, institution, product or model names;
- user-designated proper nouns, model numbers or fixed strings.

Each item declares:

- `required` — must be visible and exact; or
- `if_rendered` — may be omitted, but must be exact if rendered.

Do not put ordinary conclusions, analytical labels, full sentences, paragraphs or
stylistic wording into `fidelity_text`. Every item must be traceable to `full_copy` or an
explicit user fixed-string authority. Keep fidelity narrow so ordinary Stage 02 copy
remains rewriteable.

## 6. Protected semantic payload

The following remains non-optional whenever it changes meaning:

### 6.1 Actors and responsibility

Do not assign a task to an unsupported actor, expand one actor's state to a group, or
replace a named responsible party with an umbrella entity that changes responsibility.

### 6.2 Status and modality

Preserve distinctions such as:

- 已完成 / 已形成;
- 正在推进;
- 计划开展 / 拟开展;
- 建议;
- 可;
- 待确认;
- 尚未;
- 目标.

Do not convert `可` to `必须`, `建议` to `要求`, `计划` to `已完成`, or `目标` to
`已实现` without evidence.

### 6.3 Numbers, dates and units

Do not add, round, infer, normalize or reassign a number. When exact rendered spelling
matters, put only the minimum exact literal into `fidelity_text`.

### 6.4 Conditions and boundaries

Keep any condition, exclusion, scope, trigger, time qualifier, authority boundary or
applicability limit that changes the claim.

### 6.5 Formal instruments

Preserve the actual identity and type of policies, plans, standards, measures,
initiatives, contracts and agreements. Do not merge distinct instruments into an
umbrella term unless the source itself does so.

## 7. Speaking position and professional register

The analytical script inherits the source's issuer position unless the approved audience
brief explicitly changes the communication voice.

Do not introduce outside-narrator frames such as:

- `材料指出`;
- `文件认为`;
- `原文说明`;
- `根据材料可以看出`;
- `从材料看`.

Analytical synthesis should read as the approved report's own professional judgment while
remaining traceable to evidence and clearly bounded in strength.

## 8. Stage 02 boundary

Stage 01 owns semantic reasoning. Stage 02 owns runtime visible-copy selection and visual
expression.

For Final Script 1.2, Stage 02:

- receives `full_copy` as ordinary rewriteable content;
- derives runtime `onscreen_text` from it;
- may select, rewrite, merge, shorten, split and reorder ordinary wording;
- receives `fidelity_text` separately;
- applies exact-copy checks only to fidelity literals;
- must not reinterpret Stage 02 copy as a second Stage 01 semantic authority.

Therefore analytical AUTHOR must not create a hidden visible-script layer in
`fidelity_text` and must not pre-compress `full_copy` simply to fit a guessed image layout.

## 9. Whole-deck analytical Critic

Review:

- source chapter coverage and approved restructuring boundary;
- each page's question and conclusion;
- argument independence and evidence support;
- cross-page storyline;
- repeated evidence serving no distinct page role;
- relation direction and claim strength;
- mixed status or modality drift;
- actor and responsibility consistency;
- unsupported mechanism, capability or value synthesis;
- page density as a scope/pagination issue rather than a reason to delete semantic
  content;
- `fidelity_text` provenance, visibility choice and over-locking;
- absence of authored `onscreen` on 1.2 content pages.

Do not award quality merely because a page has a strong-sounding headline, three cards,
a Pyramid shape or a complete visual loop. The analytical claim must remain defensible.

## 10. Critic failure and rewrite policy

Rewrite from the earliest failed layer:

- wrong source scope -> repair PLAN/page scope;
- stale or blocked exact-source gate -> repair source index / packet / preflight;
- unsupported conclusion -> repair or remove `core_message`;
- invalid argument topology -> repair `argument` and the corresponding `full_copy`;
- unsupported full-copy proposition -> repair `full_copy`;
- over-broad or wrong fidelity literal -> repair `fidelity_text` after semantic content;
- optional field drift -> delete or repair the optional field;
- whole-deck duplication -> repair the smallest affected page boundary.

Do not line-edit a downstream sentence while leaving its unsupported semantic parent in
place.

## 11. Deterministic validation

After generative Critic and Rewrite, run the repository's schema, lint, semantic audit,
source-reference and delivery checks. Deterministic success verifies machine-checkable
contracts; it does not prove that analytical business entailment is sound.

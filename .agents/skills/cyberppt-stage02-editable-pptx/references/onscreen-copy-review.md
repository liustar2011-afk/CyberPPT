# Stage 02 上屏文字表达与审阅

在内容适配后、编译送图脚本前，以及展示编译结果供用户审阅时读取本参考。
本参考规定主 Agent 的表达判断和人工复核方法；程序门禁、字段和续跑方式继续使用 Stage 02 主 Skill。

## 内容与权威

从当前 canonical intake 的普通内容与独立 fidelity_text 出发，结合页面使命和已批准关系判断可见表达。Stage 01 的 full_copy 保持完整语义，不回写 authored onscreen；外部稿遵循同一表达方法。

运行时 onscreen_text/content_text 是可改写的内容素材。编译稿中保留完整素材时，如实展示为内容素材，不把它宣称为已定稿的逐字上屏文字。普通内容的最终选词与布局可由 ImageGen 完成；fidelity_text 的 required 和 if_rendered 规则分别保留。

用户审阅通过只确认当前送图内容、语义边界和表达方向，不将普通正文升级为逐字锁定文本。用户提出新增固定字符串时，先核对其明确授权与适用范围，再通过正式输入合同传递。

## 表达方法

- 需要承载多条长明细时，按具体业务对象或来源已有分类组织“业务小标题＋完整、自然的明细句”。小标题概括同组内容；短信息可保留“标签：短语”。避免把长句平铺成一串标签，也避免以通用的“需求、措施、价值”替代具体业务对象。
- 并列事实、任务、分类和状态保持可辨认的并列关系。只有脚本已批准的结论或关系才能形成总判断、因果链、递进或闭环；定义和任务清单无需强行加结论。
- 枚举可通过共享主语、合并真实重复、分组或局部重排减少冗余。保留决定含义的对象、责任、状态、数量、日期、范围和条件。来源中的不同类别、阶段或责任主体不能因压缩而合并为同一状态。
- 数字保留所指对象和必要单位；体系代码、编号及核心缩写与业务名称、作用同页可获得。关系表达保留两端主体、方向及必要条件。
- 依据 self_read/presented、页面使命和内容复杂度检查密度，不规定统一字数、固定模块数或版式。优先消除重复与调整文字分组；若必须改变页面使命、分页或关键语义，返回脚本修订流程后重新适配。

## 在现有送图脚本停点复核

复用主 Skill 的只编译模式和 compiled_deliverable_prompt 产物，不增加确认文件或第二份权威文案。

展示实际逐页送图脚本全文与绝对路径链接，并用简短说明帮助用户识别：

- 页面内容素材或实际已编写的上屏措辞，以及两者当前承担的角色；
- required 保真项和可选显示的 if_rendered 项；
- 已存在的业务分组及关系方向；
- 会影响理解的省略、密度问题或待修正内容。

复核材料必须来自本次实际编译结果，不能用对话中另写的理想文案替代。不要在审阅说明中补入编译稿没有的业务判断或暗示已经完成压缩。

发现问题时，通过正式支持的输入或关系决策路径修改并重新编译。禁止编译后替换提示词、手改 manifest 或创建平行输入绕过校验。若当前入口无法表达所需普通文案调整，明确该限制并修复正式消费路径后再交付审阅稿。

确认沿用已有送图脚本停点；同一已确认内容的失败重试无需重复确认。脚本发生实质变化时按主 Skill 重新展示并确认。

## 生图后核对

检查真实图片和最终 PPTX 的可读性、分组、数字所指、条件与关系方向。普通文案允许改写，仍须保护批准语义；逐字验收仅针对 fidelity_text。出现语义丢失或误导时回到同一批次正式修订与重编译流程，不能仅凭 OCR 通过或文件存在交付。
